《铁路复兴：沙能冲击》是一款铁路经营模拟 × 视觉小说游戏。你继承一条被世界遗忘的废弃铁路，招募员工、维护车辆、对抗垄断企业的渗透，在一个沙能飞行器统治天空的时代，证明铁轨仍有价值。

整个项目结构为 AI 工具链优化——文档、代码、数据格式统一，你可以直接用生成式 AI 实现自己的想法。

游戏的核心不是"做选择"，而是"承担过去的选择"。每一个决策都受**惯性**支配——今天的降价要 20 天才能见效，过去长期压榨的员工不会因一次加薪就忠诚，**USET** 一旦扎根就难以驱逐。这不是一个你可以读档重来的游戏；这是一个你必须与历史共处的游戏。

数据驱动的经济系统，五条相互联动的趋势线，基于 3D **Simplex 噪声**的波动引擎，确保每一局游戏的经济走势都不相同。

## 世界背景

2076 年。二十六年前，沙能还只是英国实验室里的一个原型。今天，它是新世界秩序的基石。

2050 年，英国工程师团队发明了沙能原理。次年，拥有全球最大沙子储量的朝鲜民主主义人民共和国买断了全部专利，在平壤组建了**联合沙能科学技术会社（USET）**。2053 年，首款量产沙能载具「沙子飞猪号」下线。2056 年，铁路客运量首次下降 34%。2068 年，91 个国家解散了国有铁路系统。2072 年，全球铁路网事实上已停止运营。

朝鲜——曾经的边缘国家——成了世界唯一的超级大国。不是因为军事征服，而是因为控制了驱动一切的资源：沙子。

USET 不是一家普通公司。它的股权结构精心设计，以便在国际制裁体系中游走：卢森堡控股平台名义持股 51%，**白头山动力总会社**（朝鲜国资实体）持股 49%。实际控制权通过三份不公开的协议——管理权、技术授权、沙子独家供应——牢牢握在平壤手中。账面上它是跨国企业，骨子里它是国家机器。

沙能载具有六个致命弱点：拉不动重货、闯不过风暴、飞不远长途、夜间效率低下、离不开沙子补给、受制于空中管制。铁路的六项优势恰好是这六点的镜像——这不是巧合，这是玩家必须利用的设计空间。

玩家继承了爷爷留在雾峰村（中国中部一座被雾气笼罩的茶乡山村）的废弃线路。目标是在一个已经不需要铁路的世界里，证明铁路还有存在的价值。

## 游戏结构

### 五条趋势线

每次游戏的表层之下，五条相互关联的趋势线在运行。它们在越过阈值前不会显现，一旦越过，可能触发不可逆的变化：

| 趋势线 | 定义 | 越界后果 |
|--------|------|---------|
| **信任** | 公众对铁路的信心 | 低于 30：客流雪崩式下跌 |
| **财政** | 玩家的财务状况 | 持续亏损：信用评级降级，利率上升 |
| **沙能渗透** | USET 在各城镇的市场份额 | 超过 0.60 持续 15 天：USET 建立永久营业点 |
| **政治压力** | 政府介入的程度 | 超过 0.70：线路可能被征收或强制转让 |
| **设施老化** | 线路的累积磨损 | 低于 40：状态上限永久降低 10% |

趋势线之间不是孤立的。信任崩塌会助长沙能渗透，沙能渗透侵蚀收入，收入恶化拖累财政，财政恶化加速设施老化——这是一个连锁反应，如果不加干预，可以终结一局游戏。反之，早期对信任的投入会产生正向循环，随着时间的推移不断放大。

### 核心系统

游戏由五个相互连接的模拟引擎构成，每个引擎都有独立的设计文档和公式体系：

**沙本位经济核**——经济模拟引擎。客流、燃料消耗、工资、维护成本、事故概率、公众信任，每一项都由文档化公式决定。收入减去支出得到真实数值，而非脚本曲线。引擎驱动五条趋势线；它也是受惯性原则影响最深的系统——没有哪个决策能立即见效，每一个选择都背负着过去的重担。

**千里马创世核**——世界生成系统。每次新游戏开局时，一个种子码（格式 `RR-XXXXX-YYYYY`）初始化底层结构：城市模板及其供需依赖关系、通过 Kosaraju 强连通算法计算的资源分布图、通过 Kruskal 最小生成树算法生成的铁路网、按城市簇分配的政治倾向。两次游戏体验不同，是因为底层结构本身不同——而非脚本化的随机差异。

**岁月叙事引擎**——事件生成系统。系统分析当前世界状态——种子衍生的结构、趋势线位置、员工状态、玩家与角色的关系——生成叙事事件，适应硬编码无法预见的变量。引擎采用模板化设计：每个事件类型有固定的槽位结构，WorldAnalyzer 根据运行时条件填充槽位。事件设有冷却时间、密度上限和对数衰减曲线，防止叙事疲劳。

**先民人事系统**——员工管理系统。每位员工拥有一棵技能树，覆盖五大系统（行车、机辆、线路、信号、站务）和十九个子技能，每个子技能有独立的 0–100 等级。疲劳与忠诚度刻意不在界面显示——它们通过行为流露：说话的语气、是否愿意加班、事故后的反应。系统包含师徒传承（学徒在师傅指导下学习速度×2）、社会对比效应（员工比较工资，觉得不公则忠诚下降）、以及工资谈判（技能大幅提升后触发加薪要求）。

**铁龙竞争系统**——对手 AI。USET 在每个城市维护一个渗透值，自然增长（0.0015/天）并通过营销活动加速：广告攻势、免费试乘、价格战，以及铁龙计划——一个以「铁路遗产保护」为名的收购机器，通过六步流程（筛选目标→接触→渗透→施压→收购→吞并）吞并经营困难的线路。每 30 天，USET 评估全局态势并选择策略。如果渗透率超过 0.60 持续 15 天，USET 在该城市建立永久营业点——即使渗透率回落，这个据点也不会消失。

### 惯性原则

这是游戏最核心的设计哲学：**你不是在做选择，而是在承担过去的选择。**

每个系统都存在惯性——一条历史基线，拖累或加速玩家操作的效果。公式在所有系统中统一：

```
效果 = 操作值 × (1 − 惯性系数) + 历史基线 × 惯性系数
```

| 系统 | 惯性系数 | 含义 |
|------|---------|------|
| 客流 | 0.15 | 降价需要约 20 天才能完全见效 |
| 员工忠诚 | 0.15 | 过去长期低薪的阴影不会因一次加薪而消散 |
| 沙能渗透 | 0.20 | USET 的根扎得最深，最难拔除 |
| 车辆状态 | 0.10 | 一次大修抵消不了数月的疏于维护 |
| 政治关系 | 0.18 | 失信一次，修复以周为单位 |

历史基线是 30 天加权平均：近期的权重更高。当某个系统长期低于阈值时，会产生**永久遗留问题**：一条事故记录、一个 USET 营业点、一个降低的车辆状态上限、一个政治支持降级。这些遗留问题不会因为数值回升而自动消失——它们需要数月持续的良好表现才能逐步消除。

波动引擎（L1 简单波动 / L2 加权波动 / L3 复合波动 / L4 黑箱波动）使用 3D Simplex 噪声（`noise.snoise`）提供连续、非重复的变异，确保即使底层数值相近，每一天的感受也各不相同。

### 叙事与经济

视觉小说支持三种对话模式：预设（完全编剧）、自由 AI（玩家输入任意内容，AI 以角色身份回应）、混合（预设分支 + AI 兜底）。角色带有人设、好感度阈值和对过往对话的记忆。规划中的手机 AI 助手由玩家自己的 API Key 驱动，叙事上被包装为远程调用学校服务器上的改良版 RDA（铁路决策辅助系统）。

经济模拟在前期是故意设计成亏损的。玩家靠剧情驱动的补贴生存——政府补贴、社区集资、遗产保护基金——每一项都绑定着需要维护的政治关系。补贴金额不是固定的：它由运营评估、政治关系、线路战略价值共同决定，且受惯性原则调制。

每位员工拥有技能树，而非单一线性等级体系。技能树由两层结构构成：

**母技能**——分为五大系统（行车、机辆、线路、信号、站务），对应铁路行业的真实工种划分。每个母技能等级由其下属所有子技能等级的加权平均计算得出，以数值表示（0-100），不设职级名称。

母技能与子技能之间存在双向反馈机制：子技能提升时，母技能按比例同步增长；当母技能等级高于子技能时，子技能获得追赶加成——经验获取效率随等级差距增大而提升，使资深员工在学习同系统新技能时效率高于新员工。

跨系统学习存在门槛差异。同一系统内的子技能迁移较为自然——具备驾驶技能的员工学习调车任务的效率损失较小。跨系统学习（如驾驶员学习机辆维修）则需要专门培训，效率系数显著降低。

## 游戏进程

```
序章视觉小说（Day 0–4）→ 求生 → 站稳 → 扩张 → 突破 → 发展 → 全国路网
```

游戏围绕一个隐式的三层时间模型展开：每日决策、每月评估、每年战略调整。政治周期影响补贴。随机事件——风暴、油价暴涨、节假日客流、USET 营销攻势——在不同季节施加不同压力。每一个决策都有惯性。玩家永远在——每一刻都在——背负着过去。

## AI 开发指南

AI 代理专用文档位于 `docs/for-ai/`：

| 文档 | 内容 | 必读 |
|------|------|------|
| `docs/for-ai/PROJECT_OVERVIEW.md` | 项目总览：架构图、数据流、场景流程、设计-实现差距 | ✅ 修改前必读 |
| `docs/for-ai/CODE_MAP.md` | 代码地图：类依赖关系、修改路径、资源引用、存档机制 | ✅ 修改前必读 |

**AI 代理工作流**：
1. 读 `docs/for-ai/PROJECT_OVERVIEW.md` 理解全局
2. 读 `docs/for-ai/CODE_MAP.md` 定位修改目标
3. 读相关的设计文档（`参考资料/` 或 `docs/compose/specs/`）
4. 修改代码，同步更新 `docs/for-ai/` 中的文档
5. 通过 Unity 批处理验证编译
