## 世界背景

故事发生在 2076 年。沙能飞行器终结了铁路时代：全球客运量下降 78%，91 个国家解散了国有铁路系统，至 2072 年全球路网事实上已停止运营。沙能垄断企业 **USET** 掌控天空；拥有全球最大沙子储量的朝鲜，是唯一的超级大国。

沙能载具存在六个关键弱点：重载能力有限、难以应对恶劣天气、航程较短、夜间效率低下、依赖沙子补给、受制于空中管制。铁路的六项优势与之对应。玩家继承了爷爷留在雾峰村（中国中部一座被雾气笼罩的茶乡山村）的废弃线路，目标是证明铁路仍有存在的价值。

## 游戏结构

### 五条趋势线

五条相互关联的趋势线在表层之下运行。它们在越过阈值前不会显现，一旦越过，可能触发不可逆的变化：

| 趋势线 | 定义 |
|--------|------|
| **信任** | 公众对铁路的信心 |
| **财政** | 玩家的财务状况 |
| **沙能渗透** | USET 在各城镇的市场份额 |
| **政治压力** | 政府介入的程度 |
| **设施老化** | 线路的累积磨损 |

### 核心系统

游戏由五个相互连接的模拟引擎构成：

- **沙本位经济核（Sand Standard Core）**——经济模拟引擎。客流、燃料、工资、维护、事故概率与信任均由文档化的公式决定；收入减去支出得到真实数值而非脚本曲线。引擎驱动五条趋势线。[公式参考](docs/compose/specs/跨系统联动公式.md)
- **千里马创世核（Chollima Genesis Core）**——世界生成系统。每次新游戏开局时，种子初始化底层结构：供需关系、资源分布与政治倾向。两次游玩体验不同，是因为底层结构本身不同。[设计文档](docs/compose/specs/千里马创世核.md)
- **岁月叙事引擎（Suiyue Narrative Engine）**——事件生成系统。系统分析当前世界状态（种子衍生结构、趋势线位置、玩家与角色的关系），生成能够适应硬编码无法预见的变量的事件。[设计文档](docs/compose/specs/岁月叙事引擎.md)
- **先民人事系统（Seonmin Personnel System）**——员工管理系统。每位员工拥有技能轨道、成长速度与潜力上限。疲劳与忠诚度刻意不在界面显示，而是通过行为流露——说话语气、是否加班、事故后的反应。[设计文档](docs/compose/specs/先民人事系统.md)
- **铁龙竞争系统（Iron Dragon Competition System）**——对手 AI。USET 在每个城市维护渗透率数值，自然增长并通过营销活动加速；每 30 天采取一次行动。其"铁龙计划"以"铁路遗产保护"为名，实际收购经营困难的线路。[设计文档](docs/compose/specs/铁龙竞争系统.md)

### 叙事与经济

前期纯运营亏损是设计使然；剧情驱动的补贴在生存期为铁路提供现金流。

视觉小说支持三种对话模式（预设 / 自由 AI / 混合），可在 MiMo、GPT 或本地模型之间切换。角色带有人设、好感度阈值与记忆。规划中的手机 AI 助手由玩家自己的 API Key 驱动，叙事上被包装为远程访问学校服务器、调用改良版 RDA（铁路决策辅助系统）。[设计文档](参考资料/视觉小说系统设计.md)

*[核心玩法循环](docs/compose/specs/核心玩法循环.md) · [跨系统联动公式](docs/compose/specs/跨系统联动公式.md)*

## 员工

玩家并非独自经营这条线路。团队成员开始时规模很小，并随世界发展而成长：新人加入、老人退休、学徒进入叙事。[角色设定](参考资料/角色设定.md)

## 游戏进程

```
序章视觉小说（Day 0–4）→ 求生 → 站稳 → 扩张 → 突破 → 发展 → 全国路网
```

政治周期影响补贴。随机事件——风暴、油价上涨、节假日客流、USET 广告攻势——在不同季节带来不同压力。


| 场景 | 用途 |
|------|------|
| `Scenes/VN_Test.unity` | 序章视觉小说（Day 0–4） |
| `Scenes/StationSlice_V1.unity` | 车站经营主场景 |
| `Scenes/Login.unity` · `Scenes/TitleScreen.unity` | 入口界面 |

## AI 开发指南

AI 代理专用文档位于 `docs/for-ai/`：

| 文档 | 内容 | 必读 |
|------|------|------|
| `docs/for-ai/PROJECT_OVERVIEW.md` | 项目总览：架构图、数据流、场景流程、设计-实现差距 | ✅ 修改前必读 |
| `docs/for-ai/CODE_MAP.md` | 代码地图：类依赖关系、修改路径、资源引用、存档机制 | ✅ 修改前必读 |

**AI 代理工作流**：
1. 读 `docs/for-ai/PROJECT_OVERVIEW.md` 理解全局
2. 读 `docs/for-ai/CODE_MAP.md` 定位修改目标
3. 读相关的设计文档（`参考资料/` 或 `docs/compose/specs/`）
4. 修改代码，同步更新 `docs/for-ai/` 中的文档
5. 通过 Unity 批处理验证编译
