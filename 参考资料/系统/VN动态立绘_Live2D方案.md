# VN 动态立绘：Live2D Cubism 制作与接入方案

实施前置已更新：见 [制作交付清单](../资产/Live2D制作交付清单.md)。目前角色配置、配音声源接口和岁月平板剧情阶段已准备；正式 SDK、模型及动态渲染仍未接入。

2026-11-05。用户明确希望参考《爱上火车》的动态立绘，随后点名 Live2D，认为静态立绘太僵硬。本项目建议将主要角色的制作目标转为 Live2D Cubism。本文是研究和制作方案，SDK、模型和动态播放器尚未接入，不应当据此标记功能完成。

## 已核对的项目现状

- Unity `6000.5.8f1`，URP `17.0.3`，Input System 已在 Packages 中。
- `CharacterSpriteManager.UpdateDisplay` 当前按角色、表情加载整张 PNG，UI Toolkit 槽位负责站位；未发现 Live2D/Cubism、`.moc3` 或 `.model3.json`。
- `VNVoicePlayer` 与打字机是分别驱动的系统，后续口型必须接实际语音状态，不能把吐字视为正在出声。
- 岁月已有 `normal_no_pad.png`、`smile_no_pad.png`。本轮新增 `VNPortraitStoryStage`，正常播放及回看恢复都按 `TABLET_SETUP` 前后的游标选择图片；缺少早期表情回退无平板常态。已做纯数据检查，尚未进行画面回放验收。

## 技术选择与研究依据

本项目倾向 Live2D，理由是官方已有 Unity 框架、参数与表情、动作淡入淡出、眨眼、口型及 MotionSync 的文档和接口，适合把各角色持续维护在同一套模型参数上。这是针对本项目的选择，不意味着 E-mote 不成熟。

- [Cubism Unity Components 官方 README](https://github.com/Live2D/CubismUnityComponents/blob/master/Assets/Live2D/Cubism/README.md)：当前框架面向 URP，并需要专用渲染 Pass；采用 Input System。官方列出的开发 Unity 版本为 6000.3 / 6000.0 系列，本项目 6000.5.8 的实际兼容性仍须样例验证。
- [Unity 表情接口](https://docs.live2d.com/en/cubism-sdk-manual/expression-unity/)：表情由参数叠加驱动，可结合正常动作，不必为每个表情另画整套身体。
- [口型接口](https://docs.live2d.com/en/cubism-sdk-manual/mouthmovement-unity/)与 [MotionSync Unity 插件](https://docs.live2d.com/en/cubism-sdk-manual/cubism-sdk-motionsync-plugin-for-unity/)：可先做音量驱动的基础张口，再验证预录日语语音的更细口型。没有音频就不宣称语音同步已完成。
- [SDK 官方下载](https://www.live2d.com/en/sdk/download/unity/)与 [SDK Release License](https://www.live2d.com/en/sdk/license/)：开源框架不等于完整 Core 或发布授权；导入正式 SDK 时记录版本和条款。Editor、SDK 发布与素材各自的许可分别核对。本轮未购买、安装或接受许可。

## 素材制作改法

先确定统一的正面／轻微侧转基准，而后制作真正可编辑的分层原画。每张 AI 输出 PNG 只是原画候选，不是已经拆好的 PSD，也不是可运行 Live2D 模型。各部件需要补画遮挡部分，不能直接把完整 PNG 裁出几块便当作合格模型。

首轮拆分清单：

| 部位 | 素材与用途 |
|---|---|
| 面部 | 脸底、耳朵、鼻部及必要遮挡补画；固定脸型、眼距、颈部连接 |
| 双眼 | 左右眼白、虹膜／瞳孔、高光、上下眼睑；独立开合和眼球方向 |
| 眉 | 左右眉独立；认真、好奇、傲娇等由参数组合 |
| 嘴 | 上下唇、口腔、舌齿的必要层；闭口、开口、嘴形由参数控制 |
| 头发 | 后发、刘海、两侧鬓发、发髻／发饰；转头和轻微摆动时不能露空 |
| 身体 | 颈、躯干、外套、衬衫、领带／领结；呼吸幅度克制 |
| 手臂与道具 | 前后上臂、前臂、手、瓶子或平板；道具不随嘴和呼吸产生橡皮拉伸 |
| 饰品 | 珍珠耳饰、玫瑰胸花、蝴蝶结等保留识别点，单独控制或绑定合理父级 |

建议参数从小样起步：头部 Angle X/Y/Z、左右眼开合、眼球 X/Y、眉形、嘴开合／嘴形、呼吸、轻微身体角度；先做常态、认真、温和、好奇、轻微傲娇。人物仍是正常比例主立绘，Q 版限于插画。不能靠反复独立生成整张表情图来冒充连续动态。

嘉颖徐年龄固定为 24：年轻成年脸型、小体积低盘发，保留黑西装、白衬衫、红领带、玫瑰胸花、珍珠耳饰。2026-11-05 最初四张重绘被用户指出偏老，作为失败候选保留，不替换正式立绘。后续年轻版是新的待拆分原画基准，尚未自动覆盖全套正式表情。

岁月排在嘉颖徐小样之后。必须制作两套手臂／道具姿态：

- 拿到平板前：无平板，双手及衣服被平板遮挡的位置必须补齐。
- 拆封并完成 `TABLET_SETUP` 后：可用持平板姿态，保留正确长宽比、相机与 mi 标识。
- 阶段以当前剧本播放位置和指令为依据；从存档、书签、回顾跳回拿到平板之前，也应显示无平板。不能用账号曾激活过平板的永久标记代替剧情阶段。

## 接入路径（官方模型独立验证已完成，正式VN待接入）

1. 单独小样接入官方完整 Cubism Unity SDK，先用官方样例验证 Unity 6000.5.8、URP 蒙版／透明渲染和 Windows 输出，避免把原画不合格与 SDK 不兼容混成一个问题。
2. 在现有角色站位之下增加动态展示适配层；模型通过独立相机与透明 RenderTexture 接入 UI Toolkit。该方案需验证，不声称 SDK 可直接当 `backgroundImage` 使用。保留原 PNG 渲染路径作为缺模型和性能回退。
3. 剧本继续使用现有角色 ID、`e` 表情与 `reactions`；适配层把名称映射到 `.exp3.json`／模型参数。保留存档与书签的 scene/entry 坐标，不为动态演出重排剧本。
4. 音频播放中的说话者才驱动嘴；停顿、停止、换句、重放结束立即闭口。旁白、男主和静音行不假装说话。眼睛可自然眨动，避免所有同屏角色同一时刻眨眼。读档和 seek 不重播入场动作。
5. 无平板／持平板采用道具与手臂姿态切换；不做伸缩图片来掩盖持物差异。
6. 主验收仍为 2560×1440，检查嘉颖徐与岁月／教授同屏头部比例、视线高度、脸型稳定性、眼睑遮罩、嘴部开合、发丝穿帮、UI 前后层级和内存回收。随后做 Windows Player 与 Android 平板实机验证。

第一阶段成功标准：一个嘉颖徐模型能眨眼、轻呼吸、连续切表情，播放语音时动嘴且静音闭嘴；同屏不卡比例，回看不串阶段。SDK 导入、编译通过或单张静态图看起来不错，都不能代替这个成功标准。
