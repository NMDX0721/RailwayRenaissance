# 场景交互与驾驶教学

2026-10-21。用户确认方向：参考《底特律：化身为人》的非侵入式场景交互；准心指向或靠近时浮动提示，多动作有序展示；首次教学引导自定义交互键并说明随时可改；避免背大量快捷键，硬核以实体操作为主，休闲可由小黄鼠协助复杂操作。

## 一、交互语言

对象存在、能够接近、已经聚焦、可以执行、执行成功是不同状态。附近可交互物仅作轻量提示；聚焦后才显示名称、当前状态与动作。一次主要展示一个对象，准心命中优先于邻近候选；没有视线或超出操作距离不展示可执行选项。靠近不自动操作。

提示贴近部件，在屏幕边缘内收，避免遮住该部件与主要仪表。用细线、短标签、轻量底衬和少量暖色强调；不整块高亮驾驶台，不改变原材质，不将所有对象长期贴满图标。动作面板的位置、字号与遮挡处理后续需要真实分辨率截图验收。借鉴就地呈现思路，不承诺复制《底特律》的全部交互细节。

## 二、动作排列与输入

同一对象统一列出语义动作，例如钥匙座的插入、转动、拔出；闸把的施加和缓解。当前高频动作在前，替代动作随后，破坏性或关键动作有明确文案与确认。不可执行时说明原因，不能只发红或静默失败。动作成功提示区分“已提交指令”和“设备已达到状态”，尤其是启动、充风和制动延迟。

主要操作只需要一个可自定义的“执行”输入；滚轮或点选切换当前对象的动作。后续手柄方向与触屏动作列表也复用这些语义动作，不将滚轮作为唯一入口。确认/长按的提示始终显示实际绑定，不硬编码 E。实体按钮仍可制作按压、旋转、拨动与拖拽动画，输入机制不代替机械状态模型。

快捷键是可选加速方式，统一走同一命令入口和联锁；不得成为完成硬核驾驶的必需记忆。后续增加快捷键时需要接入全局动作注册表，检测与移动、视角、平板、菜单、辅助功能的冲突，并提供更换/取消；首版仅处理驾驶交互键及本场景的保留键，不能称已完成全游戏冲突管理。

## 三、第一次教学

1. 冷车安全环境中先选择 E、鼠标左键或自定义键，实际试按后再继续。说明右上角“交互设置”可随时修改，取消改键保留旧设置。
2. 教看向/指向钥匙座，读对象提示并插钥匙；提示跟随实际动作，不按固定时间自动跳页。
3. 用钥匙座介绍同一部件的多动作：开启主控与拔出钥匙，并解释运行中为何不能拔出。
4. 开油泵、启动、观察运转灯和转速、等待充风；强调指令与机械结果有时间差。
5. 选择行驶方向、缓解空气制动和停放制动，小档牵引起步。
6. 短线路中再练习惰行、常用制动、停准、驻车与停机。紧急制动另设明确练习环境，不让玩家为普通操作反复长按。
7. 行程结束读回顾，指出一两项具体改进，随后进入下一练习。

每次只引入一个概念；提示可关闭、重开或重做。操作顺序可接受等效安全路径，不将唯一脚本顺序当成真实行车规则。教学不绕过后端联锁、不改成无限气压、不保证固定启动秒数；故障时从观测状态解释，不一直要求玩家重复无效操作。

## 四、硬核与休闲

- 两种模式使用相同物理和设备状态；“提示多少”和“谁执行”分别配置。硬核玩家也可开启文字提示与可读性辅助。
- 硬核以现场仪表和实体控制件为主，允许关闭浮动引导，但保留便捷设置入口；快捷键可用，不强迫使用。
- 休闲可委托小黄鼠执行指定流程，如按顺序完成启动辅助操作；提前展示内容、进行中的步骤、阻断原因，可随时取消或由玩家接管。
- 岁月解释、提醒并在具备接口时执行电子操作；小黄鼠负责有物理支撑的机械操作。投影不能直接施力。
- 牵引和制动的自动化范围另行确认，不默认将整段驾驶托管。自动保护、玩家操作和委托操作分别记入驾驶日志；与生涯表现一同显示辅助条件。
- 角色动画必须对应真实命令和状态；失败可反馈，不能通过动画直接写速度、气压或档位绕过守卫。

## 五、首版实现与缺口

CabSimulationReview 场景新增 CabContextInteraction，统一控制原启动部件与4个驾驶目标：就近面板、多动作、鼠标/中央准心、E/鼠标/自定义键、PlayerPrefs偏好保存、改键取消、保留键拒绝、首次设置引导、按状态推进的启动提示。旧 CabStartupPointer 保留公开射线入口用于验证，在新系统存在时停止旧鼠标逐帧处理，避免一次按键执行两次。

首版聚焦距离2.2m、近邻提示1.15m为候选可用性参数，后续按人物视点与触及范围校准；使用可用碰撞体做视线检测。驾驶室没有碰撞体的几何面不能提供遮挡判据，不能声称完整的隔墙交互防护。近邻候选仅来自已接线控制件，不扫描所有道具。

停机与大闸由全常用进入紧急位长按0.7s确认；这是当前原型防误触方案，后续要验证是否影响快速紧急操作，并提供明确且可配置的紧急操作方案。不能在此阶段视为真实安全系统。

首版浮动面板用IMGUI完成可运行原型，尚未完成最终视觉皮肤、淡入淡出、遮挡布局、完整无障碍、手柄/触屏适配。设置界面拦截驾驶交互但不暂停物理；局部教学设置不等同于经营 TutorialManager。原调试面板默认隐藏，可从交互设置打开；停放制动暂在此操作，实体部件仍待制作。

小黄鼠模型与委托执行、完整线路教学、全局快捷键映射、教学进度存档及驾驶日志尚未实现，见[辅助角色候选](../../docs/for-ai/CAB_ASSISTANT_PROPOSAL.md)和[驾驶记录与生涯](驾驶记录与生涯系统.md)。

## 六、研究与验收

[Quantic Dream官方介绍](https://www.quanticdream.com/en/detroit-become-human/flowcharts)确认PC键鼠/手柄支持，不作为本项目UI布局或交互算法的技术证据。技术参考[Unity Input Bindings](https://docs.unity.cn/Packages/com.unity.inputsystem%401.7/manual/ActionBindings.html)的运行时绑定覆盖；首版用InputAction覆盖并保存选定路径，不修改全局旧输入映射。

重点验收：准心/鼠标选择、近邻无自动操作、遮挡与距离、焦点切换不误触、改键时不执行设备动作、改键后提示同步、取消保留原键、重启保留偏好、菜单点击不穿透、长按松手/失焦取消、联锁反馈和辅助来源归因。自动测试不能代替最终视觉与可达性人工审阅。

本轮自动验证通过：`tools/compile/cab_context_interaction_pass.log`，NF5K_CONTEXT_INTERACTION_OK覆盖实际Input System E键分发、运行时鼠标绑定生效、保留键拒绝、设置期间输入隔离，以及停机长按松开取消。测试临时调整内存输入焦点策略并恢复，不保存/覆盖用户偏好。NF5K_SIMULATION_PLAYMODE_OK和15项核心检查同时通过。首次教学完整走读、改键重启持久化、最终视觉与全部遮挡场景仍待人工验收。
