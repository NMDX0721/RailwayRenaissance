# ATO 第一阶段 3D 试验线路制作要求

2026-11-05。第一阶段建议采用下列制作规格，供李海宣制作轨道、Codex 接入控制与验证。尺寸来自现有模型及源码，线路布局为本轮建议。

列车的尺寸、装配坐标、活动层级和操纵件要求见 [列车模型接入要求](ATO列车模型接入要求.md)。

## 首版布局

采用水平单线直轨，里程范围建议 s=-60 至 s=1200 米。车辆任务起点为 s=0，目标停车点为 s=900，终点之后保留 300 米。模型可分为 25 或 50 米的重复模块，避免把整条线及轨枕做成大量独立活动物体。

首版不设置坡度、超高、道岔。后续曲线、坡度实验需要同步提供路线数据，并接入模拟环境输入。

## 尺寸与坐标

| 项目 | 制作要求 |
| --- | --- |
| 单位 | 导入 Unity 后 1 单位等于 1 米，根节点缩放为 (1,1,1) |
| 轨距 | 两轨内侧净距 1.435 米 |
| 现有轨头宽度 | 0.065 米，对应两轨中心距 1.500 米 |
| 模块原点 | 起点轨道中心线、轨顶面，局部 Y=0 |
| 模块正向 | 局部 -Z，里程随前进增加；+Y 向上，X 为横向 |
| 轨顶 | 两轨等高，轨腰、轨底、轨枕和道床向下制作 |
| 参考轨枕 | 现有生成器采用长 2.6 米、沿线宽 0.24 米、高 0.106 米、间隔 0.6 米，可先沿用 |
| 层级 | 轨道、轨枕、道床、站台、标志、里程参考点分别组织 |
| 材质 | 提供轨钢、轨枕、道床独立材质槽，便于统一 Unity 材质 |

现有车辆使用约 0.461222 米有效滚动半径。当前检查线轨顶世界 Y=-1.3612222，里程零附近还有 Z=8.6 的模型偏移。这些属于旧检查场景的装配坐标。新模块按上述局部原点交付，由程序接入时进行坐标换算。

## 标记与交付

提供 FBX 或 Unity Prefab，以及以下空节点或同名清单。

- RouteStart，任务起点 s=0。
- StopTarget，目标 s=900，第一阶段用模拟后端 PositionM 所表示的车辆参考点对齐，车头停车标的外观位置另行换算。
- RouteEnd，s=1200。
- 里程标记 s=250、650、900，便于核对运行录像和日志。

标准任务现有分段限速为 0–250 米 12 m/s（43.2 km/h）、250–650 米 18 m/s（64.8 km/h）、650–900 米 10 m/s（36 km/h）。标牌用于对应任务数据。实际速度限制由控制和模拟逻辑执行。

第一版可先交付轨道和标记，站台及沿线景观随后补充。站台尺寸需结合车辆轮廓、登车结构和停车参考点单独检查后确定。

## 程序接入与验收

当前 CabReviewTrack 的生成区间为 -60 至 500 米，CabRailMotion 会根据该终点请求紧急制动，NF5KRailMotionReview 的道床生成还包含固定 560 米长度。新线接入需要同步处理采样区间、网格区间、道床长度与末端保护，并将路线中心线作为车辆循迹和轨道几何的共同来源。

验收至少完成以下检查。

1. 后端有符号 PositionM 驱动车体、转向架与车轮，停稳后轮相位固定，恢复检查点后位置一致。
2. 正常逐帧 Play 运行 900 米任务，末端保护没有在 500 米附近错误介入。
3. 记录三种控制目标的停车误差、速度违规、普通制动切换间隔、人工干预及实际停车位置。
4. 实际操作人工接管、暂停、恢复，核对界面、日志和车辆状态。
5. 检查轮轨贴合、车辆与站台净空及跟随视角，保存截图或录像。

既有自动化测试中的 Advance 循环用于验证固定步模拟和检查点。完整 3D 接入验收还需要正常帧循环覆盖 LateUpdate 的姿态投影与末端保护。

## 制作分工与模块套件（2026-11-05 更新）

分工：轨道主体由 Blender 脚本生成标准模块和贴图，Unity 编辑器脚本把模块做成预制体并按路线表拼接；站台、信号机、里程牌等有造型的物件以后用 Blender 手工建模。

**模块套件**（`tools/ato_track/build_track_module.py`，Blender 后台模式运行，输出 `Assets/Models/ATO/*.fbx`、`Textures/*.png` 和同名 `.blend`）

| 模块 | 水平长度 | 坡度 | 高差 |
| --- | --- | --- | --- |
| Track_Module_25m | 25 米 | 平直 | 0 |
| Track_Module_5m | 5 米 | 平直 | 0 |
| Track_Module_25m_Up10 / Down10 | 25 米 | ±10‰ | ±0.25 米 |
| Track_Module_25m_Up20 / Down20 | 25 米 | ±20‰ | ±0.50 米 |

- 每个模块含左右钢轨、轨枕、道床三个独立材质槽，起点在中心线轨顶，里程方向对应 Unity -Z。坡度模块的网格本身已倾斜，水平投影恒为 25 米，所以拼接只需逐段累加位置：Z 前移水平长度，Y 增加高差。5 米短件用于凑整和微调。
- 轨枕间隔 0.625 米（25 米模块 40 根，5 米模块 8 根），与上文 0.6 米参考值略有出入，目的是让两种长度都能整除。道砟表面的起伏以 5 米为周期，所以 5 米和 25 米模块在接缝处连续。
- 后续可补的模块：竖曲线过渡件、曲线模块（半径与超高）、路堤和桥梁、道岔。需要不同坡度时，在脚本的 MODULES 表里加一行即可。

**细节**
- 枕木：1024 贴图，含气孔、色差、油污与污渍，另有法线和光滑度图。每根枕木的贴图偏移不同，避免重复感。
- 道砟：道床表面带起伏和圆角砟肩，底层配碎石贴图（1 米平铺，已调暗，当作石缝阴影）。表层另有真实建模的碎石：每个 25 米模块约 8500 块，每块 20 个三角面（约 17 万面），半埋在道床里，半径 3 至 7 厘米（实际道砟约 2.5 至 6 厘米，这里略放大以便看清），枕木下不放，枕木之间的石块顶部压在枕面以下以免顶到钢轨。石块是独立对象 Ballast_Stones，使用单独材质 Track_Ballast_Stone。预制体带 LODGroup：近处（约 70 米内）显示碎石，更远只显示贴图道床。平板等低端设备可把脚本里的 STONE_DENSITY 调低后重新导出。
- 钢轨：贴图图集分两半，轨头顶面一条磨亮的运行光带，两侧偏暗；轨腰、轨底为锈蚀钢。光带宽度按 60% 轨头宽度估计，没有查到实测值。
- 道床截面（顶宽 3.4 米、底宽约 4.8 米、边坡 1:1.75、厚约 0.4 米）是估计值，应以 TB 10082 为准后再改。

**Unity 端**（`Assets/Editor/AtoTestLineBuilder.cs`）
- 菜单 Railway/ATO/Build Track Kit：设置贴图导入类型，创建材质到 `Assets/Materials/ATO`，并生成预制体到 `Assets/Prefabs/ATO`。
- 路线用一张片段表描述，例如“25 米×50 + 5 米×2”。测试线 s=-60 至 1200 米共 52 个模块，并放置 RouteStart、Marker_250、Marker_650、StopTarget、Marker_900、RouteEnd，标记高度随坡度调整。基准沿用 CabReviewTrack 的 RailDatum 与 Z 偏移 8.6 米。
- 另有套件演示场景 `Assets/Scenes/AtoTrackKitDemo.unity`：平直、+20‰、−20‰、+10‰、−10‰ 混合 23 个模块，累计升高 2.0 米后回到原高度，用于检查坡度拼接。

**验证情况**：Blender 与 Unity 批处理均已运行（日志 `tools/compile/ato_Batch.log`、`ato_Shots.log`）。测试线 Z 范围 68.6 至 -1191.4，轨顶世界 Y=-1.36，演示线最高升高 2.0 米；截图在 `tools/ato_track/review/`，目检确认贴图生效、接缝不可见。坡度交接处只做了尺寸核对，没有逐个接缝放大检查；同框车辆、真实光照下的质感也还没看。

**车辆对接**：已完成（2026-11-05）。`CabReviewTrack` 增加直线加坡度模式，`CabRailMotion` 可换线并按坡度俯仰，末端保护按线路终点计算，后端可读取路线坡度。接口选择与验收结果见 [ATO_ROUTE_3D.md](../../docs/for-ai/ATO_ROUTE_3D.md)。仍未完成：正常帧循环下的 V3 900 米闭环、人工接管与暂停恢复的 3D 验收。
