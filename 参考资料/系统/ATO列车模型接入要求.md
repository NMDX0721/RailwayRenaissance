# ATO 列车模型接入要求

2026-11-05。配套文件为 [试验线路制作要求](ATO试验线路制作要求.md)。本文件约定当前 Unity 原型的建模与程序接入方式。下列数值来自现有候选 NF5K 模型及代码，真实车辆尺寸仍需工程资料校准。

## 首批交付范围

首批使用一辆头车完成外观、两台转向架、四根轮对、驾驶室及基本操纵件。先交付能放到轨道上进行视角与运动检查的灰模，再细化材质和设备。车厢编组、车钩受力和列车管传播需要另行接入。

优先沿用项目现有 NF5K Prefab 的坐标和活动节点，在其下替换网格。提供可编辑建模源文件，以及 Unity 可导入的 FBX 或 Prefab。标明所用软件、单位、导出轴向、外部纹理和素材来源。

## 尺寸和装配基准

| 项目 | 当前接口要求 |
| --- | --- |
| 单位和缩放 | Unity 中 1 单位为 1 米，车辆根节点缩放为 (1,1,1)，父层级保持统一尺度 |
| 方向 | 车头朝局部 -Z，+Y 向上，X 为横向 |
| 车辆参考点 | 当前适配器用车辆局部 (0,0,8.6) 作为里程中点的装配偏移 |
| 轨顶高度 | 当前车辆坐标内的名义轨顶 Y=-1.3612222 |
| 有效滚动半径 | 0.461222222222 米，对应约 0.922444 米直径 |
| 转向架中心 | 车辆局部 Z=2.5 和 Z=14.7，中心距 12.2 米 |
| 每台转向架轴距 | 2.2 米，两轴分别位于转向架局部 Z=-1.1 和 +1.1 |
| 轮对旋转轴 | 局部 X 轴，轮对空节点位于轴心 |
| 车轮数量 | 两台两轴转向架，共四轮对、八个车轮 |

上述转向架坐标默认 Running_Gear 为无额外位移或旋转的装配层。轮对轴心当前位于转向架局部 Y=-0.9，其轴心高度和滚动半径对应既有轨顶。制作时以轨顶及轮对轴心对齐检查，车辆地板与轨顶分别保留各自基准。

车轮踏面、轮缘和轮背需要按左右方向正确装配。轨距按轨道两轨内侧净距 1.435 米检查，轮缘与轨头的贴合用当前轮轨参考模型复核。车体总长、总宽、总高和车门位置先按现有 NF5K 模型量取，在交付表中列出。车体外形尺寸、转向架间距或轮径发生变化时，同时给出新尺寸，以便修改适配参数和验证接触锚点。

## 活动层级

现有 CabRailMotion.Configure 通过节点名查找走行部，并读取节点的原始局部位置。保留下列结构关系。

```text
VehicleRoot
├─ BodyGeometry
├─ Running_Gear
│  ├─ Powered_Bogie_2.5
│  │  ├─ Driven_Wheelset       轴心在 Z=-1.1
│  │  │  ├─ 左车轮
│  │  │  ├─ 右车轮
│  │  │  └─ 车轴
│  │  ├─ Driven_Wheelset       轴心在 Z=+1.1
│  │  ├─ Non_Rotating_Axle_Drive
│  │  └─ 构架、轴箱、弹簧、闸瓦等
│  └─ Powered_Bogie_14.7
│     └─ 与前台相同的两轴结构
├─ CabGeometry
├─ DoorPivots
├─ ControlPivots
└─ CameraAndInteractionAnchors
```

两根轮对均为对应转向架的直接子节点，名称都为 Driven_Wheelset。现有程序要求找到两台转向架，且每台恰有两根轮对。电机、齿轮箱放在 Non_Rotating_Axle_Drive 等固定节点下，车轮和车轴放在轮对节点下。

需要接入现有悬挂和制动表现时，按既有 Prefab 保留 Primary_Coil_Spring、Axlebox、Primary_Lower_Spring_Seat、Secondary_Upper_Plate、Secondary_Elastomer_Pad、Curved_Tread_Brake_Shoe 等名称与父子关系。上压板与橡胶垫的数量和顺序需要一一对应。仅有外观用途的设备可以使用清晰的自定义名称。

## 车门、操纵件和相机

- 门扇、门把手、锁舌各自保留活动节点。门扇转轴放在真实铰链位置，滑门则提供正确的滑动方向与行程。记录关闭姿态、开启方向及开度。
- 牵引手轮、自动制动手柄、独立制动手柄、换向器和关键开关分别建模，转轴放在机构中心。交付表列出局部运动轴、零位、最大转角或行程。
- 玻璃、灯具透镜、指针、仪表底板分别保留材质或对象，供程序绑定透明度、灯光和读数。
- 提供司机眼点、驾驶视角、跟随视角与登车位置参考节点，视角检查覆盖车窗、仪表、车门和走行部。
- 交互部件保留可独立绑定的简化 Collider，便于射线选中及动作分发。实体操作仍经 CabEngineState 的既有命令与联锁接口接入。

## 网格、材质和性能

轮踏面及可见曲面保持连续法线，金属硬边使用合理倒角和法线处理。纹理、UV、切线和贴图文件随模型交付。车漆、轨轮钢、橡胶、玻璃、灯具和内饰使用清晰材质槽。

保持活动件独立，固定装饰可按材质和空间区域合并。轨枕或紧固件等重复件使用共享网格。提供面数、材质数、纹理尺寸及 LOD 情况，具体性能预算在 Windows 和 Android 平板上实测后确定。

运行姿态由模拟后端和 CabRailMotion 驱动。交付时注明模型已有的动画、Rigidbody、Collider 和脚本，程序接入时统一检查，避免同一车体被多个运动组件同时写入位置。

## 交付检查表

1. 在 Unity 用米制标尺核对轨距、轮径、轴距、转向架中心距和整车尺寸。
2. 车辆沿轨道正向前进，四轮对按同一有符号里程旋转；倒车反转，停车轮相位固定。
3. 弯道时两台转向架各自循迹，车体及部件无明显脱离、错误翻转或轴心漂移。
4. 车门与操纵件绕正确转轴运动，操纵动作经既有接口产生后端状态变化。
5. 检查轮缘净空、闸瓦间隙、车门扫掠、驾驶视野，以及与站台、地面、道旁物体的空间关系。
6. 保存和恢复检查点后，车辆位置、轮相位、操纵状态和界面读数对应同一后端状态。

模型几何与运动检查属于项目原型验收。真实轮轨接触力、车辆限界和车辆动力学结论需要各自的工程参数及验证方法。
