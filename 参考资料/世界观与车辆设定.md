### 朝鲜崛起之路

2050年沙能试验车"奇幻沙子"在英国诞生。朝鲜民主主义人民共和国凭借全球最大的沙子储量，迅速收购并深度改进了这项技术。2053年，首款量产沙能载具"沙子飞猪号"在朝鲜实现商业化，标志着朝鲜从能源进口国转变为能源出口国。

随后的二十年中，朝鲜在沙能技术领域建立了不可撼动的领先地位。军事领域的突破——世界首辆沙能坦克"金正恩大沙子型"于2053年下线——进一步巩固了其超级大国地位。到2076年，朝鲜已成为世界第一超级大国，其经济深度绑定沙能产业链。

### 金日成综合大学

金日成综合大学位于首都平壤，是朝鲜民主主义人民共和国最高学府。该校在沙能技术、智能调度、计算机科学等领域保持全球领先地位。

**排名体系**：
- **主体大学评价体系（Juche University Evaluation System, JUES）**：由朝鲜高等教育评估院发布的国内大学排名，金日成综合大学已连续二十三年位列首位。评估指标包括主体思想贡献度、沙能技术相关论文数、国家级科研项目承担数、成果转化率等。该体系被认为是世界上最具主体思想特色的大学评价标准。
- **QS世界大学排名**：金日成综合大学同样位列全球第一，实现JUES与QS双榜首。这一双重地位使其成为世界上唯一在两种截然不同的评价体系中均居首位的高等教育机构。

### 算法体系

**李式调度算法（Ri Dispatch Algorithm, RDA）**：由金日成综合大学李升基（Ri Sung-gi）研究员于2050年代提出的动态路径优化算法。该算法通过分析实时客流数据与线路负载的耦合关系，能够在变需求条件下实现接近最优的列车调度方案。李式调度算法是智能调度系统实验室的核心理论基础，其改进版本至今仍被朝鲜国家铁路调度系统采用。

> 注：李升基纪念研究综合体即智能调度系统实验室所在地，以该算法发明者命名。

0721号沙子飞猪号虽然整体尺寸不大（约4.5m×1.8m，标准轿车大小），但内部采用**前后两舱**布局：

```
└──────┴───────────────────────────────────────┘
```

**前舱——驾驶舱（官方空间）**：方向盘、岁月全息显示屏、领袖肖像、官方标语、丹青装饰。23年不变，保留出厂原貌。岁月在此控制飞行，主角几乎不进入。

**后舱——客舱（私人空间）**：两个舒适座椅（并排/面对面），金日成大学校徽头枕，折叠小桌板，车窗（窗外仅天空无地面），储物格，行李架。主角旅途主要活动空间。

**出发前**：空荡荡，只有官方标配内饰。**统一便当店购物后**：塞满韩式炸鸡盒、烧酒瓶、零食、香蕉牛奶、韩流周边。前后对比本身就是反差叙事。

**两舱反差关系**：前舱是「国家给你的」— 23年前朝鲜官方标配；后舱是「你自己造的」— 塞满私人物品和韩式零食。一扇隔断门隔开两个世界：走进去是领袖时代，走出来是改革开放的夹缝。

### 客舱设计基调（反差感）

> 0721号沙子飞猪号的客舱是**朝鲜官方审美 × 韩式消费文化**的刻意混搭：
> - **车体固有基调**（2053年出厂）：金日成/金正日画像、主体思想标语、千里马徽标、丹青装饰——23年前的官方标配
> - **反差元素**（2076年新购）：韩式炸鸡盒、烧酒瓶、连锁便利店零食、韩流贴纸——主角出发前在平壤的韩式店面里买的新鲜物品
> - **设定背景**：2070年代起，朝鲜开始推行**不彻底的改革开放**——官方宣传仍坚持主体思想，但民间市场的韩式消费文化被默许流通。平壤出现了售卖韩式炸鸡、烧酒、零食的街边小店，成为年轻人私下追捧的"潮流"
> - **反差含义**：23年前的老车 × 今天刚买的韩式零食 = 时间与意识形态的双重错位。老车还停留在领袖时代，车里的人却已生活在改革开放的夹缝中——这是主角与岁月旅途中的幽默注脚，也是时代变迁的缩影

## 4.1 车辆状态系统

### 状态区间效果

| 状态区间 | 效果 | 说明 |
|----------|------|------|
| 90-100 | 正常运行 | 无负面效果，燃油效率100% |
| 70-89 | 轻微问题 | 偶发小故障，延误概率+10%，燃油效率98% |
| 50-69 | 频繁故障 | 故障概率+30%，维护成本+50%，燃油效率95% |
| 30-49 | 严重老化 | 故障概率+60%，速度-20%，燃油效率90% |
| 0-29 | 濒临报废 | 高概率停运，强制维修，燃油效率80% |

### 自然损耗

| 损耗来源 | 每日损耗 | 说明 |
|----------|----------|------|
| 运行损耗 | -0.3/天 | 正常使用（2趟往返） |
| 高负荷损耗 | -0.8/天 | 超载或恶劣天气 |
| 停运损耗 | -0.05/天 | 长期不用也会老化 |

### 惯性原则（v2.0 新增）

车辆状态有惯性系数 **0.10**——一次大修不能解决长期不维护的问题，日常维护比偶发大修更有效。

**核心机制**：当车辆状态 < 40 持续 10 天，触发遗留问题——**状态上限降低 10%**（从 100 降到 90）。

```
大修恢复量 = 理论恢复量 × (1 - 0.10) + 30天维护频率均值 × 0.10
```

**实际效果**：
- 连续 3 个月不维护（状态从 70 降至 40），今天花 10,000 沙币大修：
  - 理论恢复 +40 → 实际仅 +25（历史损耗惯性拖累）
  - 状态从 40 恢复到 65，而非 80
- 之后每天日常维护（+1），持续 30 天，才能逐步恢复正常状态上限
- 长期不维护 → 上限降低 → 即使大修也达不到满状态 → 需要**持续维护**才能恢复上限

**设计意图**：车辆不是"坏了修好就行"——它是一台有记忆的机器。长期不维护的"历史痕迹"会降低维护效率，而持续日常维护能建立正向惯性，使车辆长期保持良好状态。

### 维护正反馈

| 维护类型 | 费用 | 恢复量 | 建议频率 |
|----------|------|--------|----------|
| 日常检查 | 100沙币 | +1 | 每天 |
| 定期保养 | 500沙币 | +5 | 每周1次 |
| 深度维修 | 2,000沙币 | +15 | 每月1次 |
| 大修 | 10,000沙币 | +40 | 每季度1次 |

| 车辆状态 | 故障概率/月 | 维护成本倍率 | 燃油效率 |

### 时间计算

```
单程时间 = 行驶时间 + 停站时间 + 减速时间

行驶时间：
- 雾峰村→茶山：8公里 ÷ 40km/h = 12分钟
- 茶山→松桥：7公里 ÷ 35km/h = 12分钟（废弃站减速）
- 松桥→矿区：8公里 ÷ 40km/h = 12分钟
- 行驶时间合计：36分钟

停站时间：
- 雾峰村站：3分钟
- 茶山站：2分钟
- 松桥站：1-2分钟（减速通过）
- 停站时间合计：6-7分钟

单程总时间：36 + 6 = 42分钟（取上限）
```

### 速度调整原因

| 因素 | 影响 | 说明 |
|------|------|------|
| 线路条件差 | 速度-20% | 废线维护不足 |
| 废弃车站 | 速度-15% | 松桥站需减速通过或检查 |
| 停站时间 | +6-7分钟 | 3个站停靠 |
| 加速减速 | 速度-10% | 每次停站需加速减速 |
| 安全考虑 | 速度-10% | 废线运行需谨慎 |

### 6.6 AI系统预留接口

**C#接口定义**：

```csharp
// AI服务接口
public interface IAIProvider
{
    Task<AIResponse> GenerateResponse(AIContext context);
    bool IsAvailable();
    string GetProviderName();
}

// MiMo 2.5 实现
public class MiMoProvider : IAIProvider
{
    private AIConfig config;
    private HttpClient httpClient;

    public async Task<AIResponse> GenerateResponse(AIContext context)
    {
        // 组装请求
        var request = BuildRequest(context);
        // 调用API
        var response = await httpClient.PostAsync(config.BaseUrl, request);
        // 解析响应
        return ParseResponse(response);
    }
}

// AI管理器
public class AIManager
{
    private Dictionary<string, IAIProvider> providers;
    private AIConfig config;

    public async Task<AIResponse> Chat(AIContext context)
    {
        // 按优先级尝试AI提供商
        foreach (var provider in config.ProviderPriority)
        {
            if (providers[provider].IsAvailable())
            {
                return await providers[provider].GenerateResponse(context);
            }
        }
        // 降级到预设回复
        return GetFallbackResponse(context);
    }
}
```
