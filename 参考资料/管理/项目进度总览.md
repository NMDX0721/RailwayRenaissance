## 五、与MiMo Code协作规范

### 工作流程
1. 发现问题 → 向MiMo Code提问，了解问题根因和当前实现
2. MiMo Code回答 → 分析答案，理解技术细节
3. 提出解决方案 → 与用户确认方案和参数
4. 用户确认 → 写最终提示词（描述需求和参数，不写代码）
5. 发送给MiMo Code → 等待实现结果

### 关键原则
- 写提示词前必须先获取当前代码的实际值，不能猜测
- 目标值就是我们要实现的效果
- 提示词格式：当前值 → 目标值（基于实际代码）
- 如果不知道当前值，必须先询问MiMo Code获取
- 不要给MiMo Code全部代码，提示词描述需求和参数即可
- 分阶段交付任务，不要一次给太多

## 六、开发环境备忘（Unity TDR 崩溃回执，2026-09-30）

**事件**：Unity 6000.5.8f1 于 2026-09-25 23:41 崩溃退出——「Failed to present D3D11 swapchain due to device reset/removed」，即 Windows TDR（超时检测与恢复）重置显卡驱动后 Unity 设备失效自杀。证据：`Logs/Editor.log` 第 7005 行；崩溃前仅资产导入活动，非 Play 中触发。

**机器环境**：RTX 5070 Ti Laptop（驱动 32.0.16.1714，2026-09-17）+ AMD 610M 核显；`nvidia-smi` 报 **NVML Unknown Error**；存在 GameViewer 虚拟显示适配器；`TdrDelay` 注册表已=10 秒（是否重启生效待确认）。

**技术支持会话回执（处置顺序）**：
1. 先确认 TdrDelay=10 是否已**重启生效**
2. **禁用 GameViewer 虚拟显示**适配器
3. 复测 NVML（`nvidia-smi`）
4. 三步无效再考虑 **DDU 干净重装驱动**
5. 兜底：Unity Auto Graphics API 切换 DX11↔Vulkan

**NVML 异常常见成因**：PATH 里旧 `nvml.dll`、NVIDIA 显示服务异常、虚拟显示驱动干扰、Optimus 切换残留、杀软拦截。

**判定**：单次崩溃未复发（曾误判为复发——识图串台，已由子代理验图纠正）。数据链完整，无需进一步行动除非复现。
