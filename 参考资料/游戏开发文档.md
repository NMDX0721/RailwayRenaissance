# 如果你想融入真正的 AI，可以怎么做？

这里我给你分成 **容易实现** 和 **进阶实现** 两类。

---

## A. 容易实现、适合高中生项目的 AI

### 1. 路线推荐 AI
输入：
- 当前需求
- 车站拥堵情况
- 货物优先级

输出：
- 推荐路线
- 推荐发车时刻
- 推荐列车数量

这不一定要深度学习。  
你可以用：
- 规则系统
- 评分系统
- A* / Dijkstra
- 简单决策树

这就已经能算“AI玩法”。

---

### 2. NPC 自适应对话
不是纯 GPT 式自由生成，而是：
- 关键词匹配
- 状态驱动
- 模板拼接
- 记忆触发

比如：
- 如果玩家上次迟到，NPC 会抱怨
- 如果玩家连续三天准点，NPC 会信任你
- 如果玩家修复了车站，商人会改变语气

这会让游戏显得“智能”。

---

### 3. 自适应难度
AI 根据玩家表现调整：
- 任务难度
- 延误频率
- 客流量
- 事件密度

比如新手期更宽松，后期更复杂。

---

## B. 更进阶的 AI
如果你时间足够，可以做这些：

### 1. 乘客需求预测
根据：
- 星期几
- 季节
- 天气
- 节假日

预测车站客流量。

### 2. 事件生成器
AI 根据世界状态自动生成故事事件。

### 3. 语音/文本剧情助手
如果你会接 API，可以让 NPC 对话带有更自然的互动。  
但这个要注意：
- 需要审核
- 可能成本高
- 可能影响可控性

import os
import requests
import json

# 🌐 获取环境变量里的 API Key
API_KEY = os.getenv("GOOGLE_API_KEY")

# 🧾 请求头
headers = {
    "Content-Type": "application/json",
    "Authorization": f"Bearer {API_KEY}",
}

# 🎯 生成剧情事件的函数
def generate_ai_story(prompt_text):
    """
    使用 Gemini API 生成剧情、任务或事件内容
    """

    # 请求体（body）
    body = {
        "model": "gemini-2.5-flash-lite",  # 免费层常用模型
        "prompt": {
            "messages": [
                {"role": "system", "content": "你是一个创造游戏剧情的AI助手。"},
                {"role": "user", "content": prompt_text}
            ]
        },
        "temperature": 0.7,
        "maxOutputTokens": 300
    }

    # 发起 POST 请求
    response = requests.post(
        "https://api.ai.google/v1beta2/models/gemini-2.5-flash-lite:generateText",
        headers=headers,
        data=json.dumps(body)
    )

    # 错误检查
    if response.status_code != 200:
        print("Error:", response.status_code, response.text)
        return None

    data = response.json()

    # API 返回的文本
    if "candidates" in data:
        text_output = data["candidates"][0].get("output", "")
        return text_output.strip()
    return None


# 🧪 示例调用

三、哪些是“不可逆”的（核心设计决定长期性）

这些一旦发生，会长期影响游戏走向并创造“历史线”：

居民信任跌破阈值（例如 30%）：客流进入「衰退期」，短期内即便修复事故，也难恢复到原值（只能通过高成本长期活动逐步恢复）。

线路被官方/竞对拆除或划为禁运：拆除与改造成本极高，且会导致该区域进入“被沙能占领”轨道。

国家/市政签署长期合约（lock-in）：例如将某城市公交承包给沙能企业（政治层面锁死），玩家再也拿不到关键收益来源。

关键资源点被沙能控制或枯竭：若资源分布是“集中型”，失去它相当于区域性瘫痪。


不可逆并不一定意味着“终局”，而是会把游戏推到一条新的难走路线（新的挑战／新的玩法）。

四、把你说的“政治倾向”和“资源分布逻辑”用可执行规则化

政治倾向（在世界种子里定义）→ 影响“当稳定度下降时”的结算策略

authoritarian（威权）

当 Stability < 0.6：政府强制分配你的列车给关键民生订单，玩家被征用；Stability +0.1，但收入 -20%。


market（市场）

当 Stability < 0.6：价格自由浮动，订单价格乘以 1 + demand_surge（玩家可趁机高价承接），但低收入区域需求萎缩（信任下降）。


welfare（福利）

当 Stability < 0.6：政府补贴部分运输费（玩家收入稳定），同时系统效率下降（运输时间增加 10%）。



资源分布逻辑（定义资源在地图上的“形态”）

在世界种子里，对每种资源（能源、农产、矿产、高价值货）定义分布类型：

集中型：少量节点产出，占比 > 40%（单点失败致命）

分散型：多数节点小规模产出（抗打击能力高）

高价值+政治：产地受政治干预（高概率触发征用/争夺）


玩法影响示例

集中型能源断供 → 全图 Stability 大幅下降 → 若政治为 market 则价格飙升（玩家可赚），若 welfare 则财政补贴但效率降低（玩家长期苦）。

分散型农产问题 → 仅局部城市小幅波动，更多是优化 vs 微调。

二、具体机制说明（可落地细节）

1) 列车（Rolling stock）

每辆车有属性：speed, capacity, comfort, reliability, fuel_type, maintenance_cost, prestige。

“名列车”（现实著名列车作灵感）作为稀有/宣发道具：例如“东方快车类”（高 prestige，能提升乘客信任/旅游线需求），但维护高成本。

可搭配：车体改装、车皮/主题（cosmetic），并影响乘客好感/票价弹性。


示例属性（缩略）

{
  "train_id":"orient_express_clone",
  "name":"东方快车纪念号",
  "speed":160,
  "capacity":240,
  "comfort":0.9,
  "reliability":0.85,
  "maintenance_cost":120,
  "prestige":0.9,
  "unlock_requirement": {"tech":"tourism_line","cost":50000}
}

2) 人员管理（Crew）

职位：驾驶员、检修、乘务、调度、PR。

每人有属性：skill_level, fatigue, salary, loyalty, specialty（如 night_shift、cargo_expert）。

培训：投入时间+金钱提升 skill_level（长期生效）。

排班：决定 fatigue 累积速率与事故概率。疲劳影响 reliability。

培养方向：驾驶员可走“高速度训练”或“安全训练”分支（影响 speed max 或 reliability）。


示例 Crew JSON

{
  "crew_id":"drv_001",
  "name":"L. Carter",
  "role":"driver",
  "skill":0.6,
  "fatigue":0.2,
  "salary":300,
  "loyalty":0.7,
  "specialty":"nightshift"
}


---

3) 机库 / 基建升级

机库等级影响维修速度、并发维修数、检修质量。

车站升级影响 上/下车效率、乘客体验（comfort）。

升级要有建造周期（慢节奏），并可能触发政治/舆论（施工扰民）。

News 有类型：info, warning, scandal, editorial，并带有影响（调整 trust、political_tendency 权重、公众情绪）。

7) 任务/订单（环境挂钩）

任务来源：城市生产（industry_tags）、season、news、VIP请求。

任务不是孤立，而是挂在“趋势+位置”，例如暴雨会增加货运延误任务、旅游季会生成高收益旅游班次任务。

任务有时间窗口（慢节奏中可长达数天/周），完成与否影响 trust、money、political favor。

8) Rival（沙能）与市场动态

沙能公司以渗透率（penetration）存在于每城市/区域，随时间上升，影响乘客选择与政治压力。

玩家可通过公关、合作、价格战、技术合作来影响渗透率曲线。

沙能事件（广告攻势、示范线路）为长期策略影响，而非频繁突发事件。

三、慢节奏下的数据/概率公式（可直接用来实现）

（这些公式简单、可调节，便于快速迭代）

1. Passenger demand per day on line L:



demand = base_population * (1 + tourism_factor) * trust_line * season_modifier

2. Accident probability on segment s per period:



p_accident = base_incident + (1 - infrastructure_health[s]) * age_factor + fatigue_factor * crew_risk

3. Trust change on event:



trust_delta = success? +0.01 * prestige_modifier : - (0.03 + severity*0.05)

4. Crew fatigue accumulation per day:



fatigue += work_hours/standard_hours * (1 - rest_quality)

5. Maintenance effect:



infrastructure_health += maintenance_level * repair_rate - decay_rate

五、核心玩法与慢节奏系统（系统宪法）

5.1 系统三条铁律

1. 世界连续运行（没有回合制弹窗）；


2. 玩家决策是长期姿态（定位、维护、人力、对外策略）；


3. 真正重要变化慢但不可逆（代际信任断层、资源被控制、政治合约被锁定）。



5.2 五条长期趋势（核心可调变量）

每个世界/存档维护这些趋势（以 0–1 或实数曲线表示）：

TrustTrend（铁路信任趋势）

FiscalTrend（财政压力 / 财政健康）

SandPenetration（沙能渗透率）

PoliticalPressure（政治干预强度）

InfrastructureDecay（基础设施老化）


这些趋势在后台按日/周被累积和结算，只有跨阈值时才会产生明显结构性变化或新闻弹窗。

5.3 玩家长期可选姿态（四类）

线路定位（每条线：民生/商业/旅游/边缘）

维护策略（紧缩/标准/过度）

人力策略（培养/外包/压缩）

对沙能的长期态度（抵制/接驳/合作）


这些姿态的切换需要成本并有滞后期（例如切换定位 30 天生效），避免频繁滥用。

5.4 不可逆点示例

trust_city < 0.3 持续 X 天 → 进入“代际断层”，新人口默认不坐火车（长期损失）

线路被政府征用/划为禁运 → 巨额拆除/重建成本且市场锁死

七、主要系统模块（详细说明与示例）

7.1 世界生成（结构随机）

目标：生成具有内在逻辑的世界骨架（不是单纯事件随机）。

生成步骤（伪代码）：

1. 生成 N 个城市（属性：population, industry_tags, geography）


2. 按规则分配资源类型（energy/agri/mining/high_value）并决定分布型（concentrated/dispersed/political）


3. 生成城市依赖图（directed graph）：谁依赖谁（电力/原料/港口）


4. 生成初始政治倾向（national & per-city）


5. 用 MST + random extra edges 生成铁路基础网络



示例 seed JSON（之前文档提供，可直接使用）

7.2 资源分布逻辑（为什么资源在这里）

concentrated（集中型）：少数节点供应大部分产能——单点失败致命。

dispersed（分散型）：多点小规模产能——抗打击强。

high_value_political：产出重要且引来政治干预（如战略矿产），容易引发征用/争夺。


影响：运距/单点风险/政治关注度/是否能掀起连锁崩塌。

7.3 政治倾向（反应方式，不是事件）

政治倾向决定“当趋势恶化时世界如何结算”，例如：

authoritarian：强制分配 & 限流（Stability +, revenue -）

market：价格自由浮动（部分玩家盈利，但穷城衰退）

welfare：补贴维持（效率下降、财政负担）


实现：在阈值发生时调用对应结算函数（policy handlers）。

7.4 列车 / 名列车系统

属性：speed, capacity, comfort, reliability, maintenance_cost, prestige, fuel_type
名列车：提升旅游线/Prestige，但维护高、保险高、可能需要特殊车库。

示例 train JSON（见上文）。

7.5 Crew（人员）系统

岗位：driver, mechanic, conductor, dispatcher, PR
属性：skill, fatigue, salary, loyalty, specialty
系统行为：

排班影响 fatigue 与 accident risk

培训投入长期提升 skill（分支化成长：speed vs safety）

crew_shortage 导致 reliability 下降


7.6 Depot / 基建升级

功能：决定维修能力、并发修列数、检修效率。
升级周期长，可能触发新闻或政治影响。升级成本高，需要玩家权衡财政。

7.7 乘客与名乘客（Human Interest）

线路级好感度矩阵：每条线维护一个 trust 值

名乘客：有名字、有故事、有政治/商业身份，与玩家互动可触发任务或政策支持

互动：dialogue choices（未来可由 AI 生成）与 gift/assistance 系统


7.8 任务/订单系统（环境挂钩）

任务由 city.industry_tags + season + news 决定

时间窗为天/周规模（慢节奏），完成与否影响 trust & revenue

任务不是孤立的：与趋势/资源/政治有内在耦合


7.9 沙能竞争体（Rival）

每城市维护 sand_penetration（0–1）

沙能公司行为：广告攻势、试乘推广、战略合作、价格战

玩家应对：PR、合作/竞争策略、接驳设计、法律诉讼（政治层面）

十二、平衡数值与公式（参考实现）

> 下面公式为原型级建议，发布前需大量测试与调整。



12.1 客流（某线路 L）

demand_L = population_weight * (1 + tourism_factor) * trust_line * (1 - sand_penetration_city)

12.2 收入（每日）

revenue = ∑ (demand_L * fare_L) + freight_income - operating_costs - maintenance_costs

12.3 事故概率（segment s）

p_accident_s = base_incident + (1 - infra_health_s) * age_factor + crew_fatigue_factor

12.4 信任变化（city）

trust_delta = - accident_severity * exposure_coef + positive_service_events*0.01 + VIP_action*0.02 - sand_ad_campaign_effect

12.5 沙能渗透更新（city）

pen_new = pen_old + ad_effect * (1 - government_regulation) - player_pr_effect

base_passengers = int(population_factor * trust * demand_multiplier)
fare = 5
daily_income = base_passengers * fare

train_condition -= decay_rate (比如 0.5 每日)

p_failure = max(0.01, (100 - train_condition) / 500)  # condition 越低概率越高

人员疲劳/效率（简单处理）：

import random
import time

# ---- 初始场景（可改） ----
state = {
    "day": 1,
    "money": 2000,
    "population_factor": 25,
    "trust": 0.60,            # 0..1
    "train_condition": 70.0,  # 0..100
    "train_capacity": 30,
    "crew": [
        {"id":"drv_1","name":"司机","role":"driver","skill":0.6,"fatigue":0},
        {"id":"c1","name":"张工","role":"idle","skill":0.4,"fatigue":0},
        {"id":"c2","name":"李阿姨","role":"idle","skill":0.3,"fatigue":0},
        {"id":"c3","name":"王小弟","role":"idle","skill":0.35,"fatigue":0}
    ],
    "train_out_of_service_days":0,
    "messages": []
}

# ---- 参数 ----
FARE = 5
DECAY_RATE = 0.4     # 每日机车自然下降
REPAIR_AMOUNT = 12   # 一次整备修复量
REPAIR_COST = 250
OUTSOURCE_REPAIR_COST_PER_DAY = 300

# ---- 助手函数 ----
def daily_passengers():
    # 基于 population_factor 和 trust 得到客流（在 20..30 范围浮动）
    base = state["population_factor"]
    approx = int(max(5, min(state["train_capacity"], base * state["trust"] * 1.2)))
    # 随机微波动
    return max(0, approx + random.randint(-2,2))

def check_failure():
    # 故障概率随 condition 降低而升高
    cond = state["train_condition"]
    p = max(0.01, (100 - cond) / 500.0)  # condition 0 -> p=0.2 ; cond100 -> 0.01
    return random.random() < p

def trigger_engine_failure():
    days = random.randint(1,3)
    state["train_out_of_service_days"] = days
    state["messages"].append(f"内燃机故障！列车停运 {days} 天，需要检修。")
    # trust 下降（即时反应）
    state["trust"] -= 0.08
    if state["trust"] < 0: state["trust"] = 0.0

def attempt_vip_meeting():
    # 需要 high trust 才能成功概率高
    base_prob = 0.2 + (state["trust"] - 0.5)  # trust=0.6 -> 0.3
    base_prob = max(0.05, min(0.9, base_prob))
    if random.random() < base_prob:
        grant = random.randint(400,1200)
        state["money"] += grant
        state["messages"].append(f"会面成功！市政府拨款 {grant} 元支持线路维护。")
    else:
        state["messages"].append("会面未果：未能争取到拨款。对方态度冷淡。")

def end_of_day_update(actions):
    # actions: dict with keys set by player this day
    # 收入
    passengers = 0
    if state["train_out_of_service_days"] > 0:
        state["messages"].append("今日列车未运行，暂无客运收入。")
    else:
        passengers = daily_passengers()
        income = passengers * FARE
        # 如果有售票员（role 'ticket'), 提升收入 10%
        ticketers = [c for c in state["crew"] if c["role"]=="ticket"]
        if ticketers:
            income = int(income * 1.10)
        state["money"] += income
        state["messages"].append(f"今日载客 {passengers} 人，收入 {income} 元。")
    # 维护消耗
    if actions.get("prepare"):
        # 需要至少一名 mechanic (role 'repair' 或 idle 自动)
        state["train_condition"] += REPAIR_AMOUNT
        state["money"] -= REPAIR_COST
        state["messages"].append(f"进行了整备：机车状态 +{REPAIR_AMOUNT}，费用 {REPAIR_COST} 元。")
    # 巡线减少事故概率（把一个闲置设为巡线会在计算时体现）
    # 清洁增加 trust 小幅
    if actions.get("clean"):
        cleaners = [c for c in state["crew"] if c["role"]=="clean"]
        if cleaners:
            state["trust"] += 0.01
            state["messages"].append("站台清洁提升乘客满意度。")
    if actions.get("patrol"):
        patrols = [c for c in state["crew"] if c["role"]=="patrol"]
        if patrols:
            # 把 train_condition 小幅保护
            state["train_condition"] += 1.5
            state["messages"].append("巡线降低隐患，机车状况略有改善。")
    # 人员 fatigue 累积（简单）
    for c in state["crew"]:
        if c["role"] != "idle":
            c["fatigue"] += 0.07
            if c["fatigue"] > 1:
                c["fatigue"] = 1.0
    # 自然衰减
    state["train_condition"] -= DECAY_RATE
    if state["train_condition"] > 100:
        state["train_condition"] = 100
    if state["train_condition"] < 0:
        state["train_condition"] = 0
    # 故障处理与检测
    if state["train_out_of_service_days"] > 0:
        # 如果有人在 repair 岗位，修复速度更快
        repairers = [c for c in state["crew"] if c["role"]=="repair"]
        if repairers:
            # 修好一日
            state["train_out_of_service_days"] = max(0, state["train_out_of_service_days"] - 1)
            state["train_condition"] += 10

def parse_player_input(text):
    text = text.strip()
    if not text:
        return None
    # 先检测是否纯数字（允许中文数字）
    # 中文数字转换（简单实现）
    zh_num_map = {"一":"1","二":"2","三":"3","四":"4","五":"5","六":"6","七":"7","八":"8","九":"9","零":"0"}
    # 把中文数字替换为阿拉伯数字
    for k,v in zh_num_map.items():
        text = text.replace(k, v)
    # 查找第一个数字
    m = re.search(r"\d+", text)
    if m:
        key = m.group(0)
        if key in COMMAND_MAP:
            return COMMAND_MAP[key]
    # 直接中文/英文关键词匹配（尽量精准）
    # 先精确匹配
    for k,v in COMMAND_MAP.items():
        if k in text:
            return v
    # 再尝试按空格分词（英文）
    parts = text.split()
    for p in parts:
        if p in COMMAND_MAP:
            return COMMAND_MAP[p]
    return None

        entry = json.loads(line)
        print(f"第{entry['day']}天｜{entry['type']}｜{entry['text']}")
    continue

推荐：做“可选时代”启动：

AI 嵌入（人物系统）——如何做（工程级）

目标：AI 驱动的对话增强人物深度，但非必需路径。实现策略分三层：

层级设计

1. 模板层（必须先做）：所有 NPC 都有模板化对话与分支（本地 JSON），可离线运行。


2. 可替换层（可选）：AI 用来生成更丰富的台词/新闻/信件（本地化中文优先）。


3. 情感驱动层（深度）：AI 输出受 NPC 状态驱动（favorability、trust、recent_events），语气随之变化。



NPC 状态（最小可用 Schema）

{
  "npc_id":"vip_mayor_01",
  "name":"陈市长",
  "role":"mayor",
  "favorability":0.42,       // 0..1
  "last_met_day": 12,
  "scandal_count": 0,
  "trust_offset": 0.0,
  "dialogue_history":[
    {"day":5,"tone":"neutral","topic":"maintenance"}
  ]
}

对话生成变量（用于 prompt）

npc.name, npc.role, npc.favorability, global.trust, recent_event_summary, player_action_summary

这些变量构成 prompt 的上下文，AI 根据 favorability 决定语气（礼貌/冷淡/敌对/支持）


示范 Prompt（中文优先，给本地模型或服务用）

你是游戏中名为“陈市长”的角色。当前状态：
- 好感值 favorability=0.42（0-1）
- 城市信任 global_trust=0.36
- 最近事件：本周线路发生两次延误（简述）
玩家今天请求拨款用于线路整备。请以中文写出一段短对话（约2~3句），反映出陈市长的态度（favorability 越高越支持），并提供两个玩家可选择的回应。返回 JSON: {"npc_utter":"...","choices":[{"text":"...","effect":{"favorability":..., "grant_prob":...}}, ...]}

本地 vs 云端决策（针对你在中国的实际情况）

开发期：先用模板 + 本地小模型（.gguf，llama.cpp）或直接用内置模板（fake AI）。

发行期：优先本地量化模型（0.6–3B），按需下载模型包；或把 AI 作为可选 DLC（节省安装包）。

离线优先：若设备不支持，自动回退模板对话。


技术实现要点

一个 ai_adapter 抽象层（同之前 demo），支持 fake / local-llm / cloud 三种模式。

对话请求带上 npc_state + last_events，AI 返回结构化 JSON（文本 + 选项 + 建议效果）。

对话结果写入日志（history），更新 npc_state（favorability、last_met_day 等）。
