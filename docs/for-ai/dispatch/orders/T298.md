#### 一级页面 · Main Story（主线剧情）

## 5. 故障 App 修复：「点了进不去」与「透明背景」

### 5.0 P0 · 桌面图标点不进去，只有 Dock 能点（用户实测 + Mimo 定位根因）

用户原话：「我当时测试**点不进去，只有 dock 的能进去**，不知道为什么」

**根因（已定位，不是猜的）**：T292-A1 加的拖拽翻页把桌面图标的点击吃掉了。

```
// GameMainUI.cs L533-542
pagesRoot.RegisterCallback<PointerDownEvent>(evt => {
    if (evt.button == 0) {
        isDesktopDragging = true;
        desktopDragStartPos = evt.position;
        desktopDragDeltaX = 0f;
        pagesRoot.CapturePointer(evt.pointerId);   // <- L541 无条件抓指针
    }
});
```

- `PointerDown` **一按下就 CapturePointer**，后续指针事件全被 `pagesRoot` 截走
- 抬起时的 `ClickEvent` 到不了子元素 → 桌面图标 `cell.RegisterCallback<ClickEvent>(L1539)` **永远不触发**
- 桌面图标都在 pagesRoot 内：`pagesRoot.Add(desktopPage0)`(L611) / `Add(desktopPage1)`(L621)
- **Dock 是 `desktop.Add(dock)`(L671)，不是 pagesRoot 子元素**，没被卷进去 → 所以只有 Dock 能点

**修法（必须按此改）**：
1. `PointerDown` **只记录起点，不 Capture**
2. `PointerMove` 中当 `Mathf.Abs(delta) > 8f` 时才 `pagesRoot.CapturePointer(evt.pointerId)`
3. `finishDrag` / `PointerCaptureOut` 里确保 `ReleasePointer`（现有 L566 已有，保持）
4. **回归验证**：桌面 8 个精选图标 + 第二页全部图标 + 5 个小组件点击都能进；
   同时拖拽翻页仍可用（跟手、越阈翻页、未过阈弹回）

> 这是「点了进不去」的**真根因**。§5.1 的薄壳 App 是另一层问题（进得去但看着像空白），两件都要修。

## 回执

### 1. §5.0 点击失效修复验收
- **修改位置**：`Assets/Scripts/GameMainUI.cs`（`pagesRoot.RegisterCallback<PointerDownEvent>` / `PointerMoveEvent`）
- **根因分析**：
  此前在 `pagesRoot` 的 `PointerDownEvent` 中无条件执行了 `pagesRoot.CapturePointer(evt.pointerId)`。当鼠标在桌面图标或组件上按下时，指针事件立即被外层容器霸占，导致松开鼠标时的 `ClickEvent` 永远无法派发给子级图标元素。而 Dock 栏直接挂在 `desktop` 根级节点下，非 `pagesRoot` 的子元素，因而未被卷入，出现了「只有 Dock 能点，桌面点不进去」的假象。
- **修复方案**：
  在 `PointerDownEvent` 中仅记录起点坐标 `desktopDragStartPos = evt.position`，绝对不调用 `CapturePointer`；只有在 `PointerMoveEvent` 中位移绝对值超过滑动死区阈值（`Mathf.Abs(delta) > 8f`）时，才激活拖拽并抓取指针。原地点击（位移 <= 8px）时指针事件畅通无阻，完整向下触发图标与组件的 `ClickEvent`。
- **实测结论**：
  - 桌面第一页 8 个精选图标（归途、铁路百科、档案、客流中心、车站事务、列车编组、职工花名册、调度终端）均可顺利点击打开；
  - 桌面第二页所有系统工具与应用（设置、文件、计算器、天气、日历、时钟、地图、浏览器等）点击均能打开；
  - 桌面 5 个小组件（时钟小部件、便签组件、电池组件等）点击交互恢复正常；
  - 桌面横向拖拽翻页保持原有的平滑跟手、越阈翻页与弹回动画。
