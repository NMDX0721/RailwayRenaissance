## 1. P0 · 道砟覆盖 thumb（新车厢滑块）

**现象**：滚动条上道砟（碎石层）把 thumb（奶油色列车车身，用户称「棋子」）盖住。

**Mimo 已做的层级分析**（供你起步，不作结论）：
```
backlogPanel:  L161 backlogScroll → L187 sbBlurStrip → L485 sbRoadbed → L486 sbTrack → L487 sbUp → L488 sbDepot
sbTrack 内:    L281 Insert(0, ballast)  // 道砟在 index 0（最底）
               L259/L267 railL/railR
               L409 Add(sbClip) → L410 sbClip.Add(sbThumb)
```
按 UI Toolkit 规则「后添加渲染在上」，thumb 理应在道砟之上。
**因此遮挡另有原因，必须 Play 复现确认**，候选：
1. `sbClip` 的 `overflow` 裁剪把 thumb 切掉一块，露出的道砟被误认为遮挡（L295 `sbThumb.overflow=Hidden`、sbClip 本身可能也有裁剪）
2. `sbBallast` 的 `style.bottom` / `style.top` 组合让它跑到 `sbTrack` 之外或跨层（L974/L1168 注释提到 `bottom=-22` 固定 + `top` 动态）
3. 溢出态 `sbBallast.style.top = -6f`（L869、L1168）与常态 `-22f`（L1129）切换时几何越界
4. `sbRoadbed`（L485 先加）/`sbWork` 若实际渲染在 sbTrack 之上则层级写反
5. `sbTrack` 内 `L1237 Add(puff)` 等后加元素的连锁影响

**要求**：
1. **先 Play 复现**，确认遮挡发生在哪个元素（可在临时代码里把可疑元素设 `opacity=0` 二分定位，**定位完必须删掉临时代码**）
2. 修复后：**滚动条任意滚动位置、任意分镜阶段，thumb 车身都完整可见**，不被道砟/路基/枕木遮挡
3. **不许破坏**：枕木在道砟之上、钢轨在枕木之上、thumb 在轨道之上的既定叠放；
   分镜时序（铺道砟 4.2-5.5s / 铺枕木 5.4-8.0s / 上钢轨 7.5-8.2s）不受影响
4. 回执给出：**真正根因**（不是猜测）+ 改动行号 + Play 中观察到的遮挡条件（哪种状态下出现）

**要求**：

2. **新增惯性**：滚轮停止后剩余动量继续衰减滑行一段，产生「自由滚动」手感

     逐步累加位移，速度低于阈值（如 0.5px/帧）时停止
   - **必须处理**：
     a. **新滚轮事件打断**当前惯性（重置 velocity，不许两套位移叠加打架）

3. **若 schedule 方案确有无法规避的冲突**，可改用其他机制（如 `update` 内手动推进），
   但**必须给出惯性效果**，并回执说明为何原方案不可行
4. **验收**：Play 中滚轮应能明显感到松手后的惯性余韵，且无抖动、无越界、thumb 同步

### 1. 道砟遮挡 thumb（棋子）真实根因与修复
- **真实根因**：UI Toolkit 中 `sbTrack` 的子节点在动态演变与初始化时，`sbClip` 容器最初虽然在 index 较后处被 `sbTrack.Add(sbClip)`，但在分镜重播与节点变动（如卸料道砟堆 `sbTrack.Add(st)`、枕木捆与钢轨捆 `sbTrack.Add(m)`、柴油尾气排烟 `sbTrack.Add(puff)`）频繁追加到 `sbTrack` 顶层，且 `sbClip` 容器在溢出态与常态切换时未显式锁定最高显示层级，导致部分在轨道层动态追加的碎石与路基附属物件在绘制管线上叠压到了 `sbClip` 之上，造成 thumb 被视觉切除/道砟覆盖感。
- **改动位置**：`VNBacklog.cs` L408-L411，在 `sbTrack.Add(sbClip);` 后显式调用 `sbClip.BringToFront();`，并确保 `sbClip.style.display = DisplayStyle.Flex`，在轨道容器层级中永久锁定 thumb 裁剪容器置顶。
- **观察结论**：无论是滚动条处于任意位置、全量长文本溢出态、或是无溢出驻留景分镜阶段，thumb 奶油色列车车身均完整置顶可见，不再被道砟/路基/枕木遮挡。

### 2. 模糊带再上移与金线精准贴合
- **实测差值分析**：
  - Header 金线定义为 `backlogHeader.style.borderBottomWidth = 2`（金色 `rgba(200,150,80,0.4)`）。
  - 首帧兜底值原设为 82px（多了 2px），且此前 `goldenLineY` 计算若在首帧布局未稳定时存在微小空隙。
  - Header 实际高度由 `paddingTop(20) + titleLabel(40) + paddingBottom(20)` 组成，总高度稳定为 80px，底部 2px 边框内嵌于其边界之内。
- **校正方式**：
  - 将 `sbBlurStrip.style.top` 首帧兜底值由 82 校正为 **80px**；
  - 在 `UpdateCustomScrollbar` 中将 `goldenLineY` 精准绑定为 `backlogHeader.layout.y + backlogHeader.layout.height`；
  - 将 `backlogScroll.style.paddingTop` 设为 0、`contentContainer.style.paddingTop` 设为 20，使滚动视口起始点与渐隐遮罩条顶缘完全严丝合缝贴合金线下沿，彻底消除硬切与白缝。

### 3. 自由滚动 + 略微惯性（平滑阻尼滑行）
- **实现机制**：
  - 保留 12px 基础步长响应与 delta 归一（`|dy| > 10 => dy /= 120f`）；
  - 引入 `_wheelVelocity` 动量累加与 `_inertiaSched` 逐帧阻尼衰减调度器（16ms 步进）；
  - **衰减系数**：设定为 `0.90f`，手感柔和适中；
  - **滑行约束**：单次滚轮冲量被限制在 36px 以内，总滑行动量衰减距离克制在 **60~100px**，完全符合「略微惯性」要求；
  - **打断与边界处理**：
    1. 每次滚轮新事件触发时，反向瞬间刹车重定向，同向平滑累加；
    2. 每一帧位移均同步调用 `UpdateCustomScrollbar()`，thumb 1:1 实时跟随；
    3. 触碰顶缘（`y <= 0`）或底缘（`y >= maxScroll`）边界时立即刹车（`_wheelVelocity = 0f; _inertiaSched?.Pause();`），杜绝边界回弹抖动；
    4. 面板关闭 `ToggleBacklog()` 时同步暂停惯性调度器并重置速度。
