## 1. 滚轮：刻度滚动 → 自由（连续）滚动

### 现状（已定位）
`VNBacklog.cs` L162-173：

```csharp
backlogScroll.RegisterCallback<WheelEvent>(e =>
{
    e.StopImmediatePropagation();
    float dy = e.delta.y;
    if (Mathf.Abs(dy) > 10f) dy /= 120f;
    float y = Mathf.Clamp(backlogScroll.scrollOffset.y + dy * 40f, 0f, SbMaxScroll());
    backlogScroll.scrollOffset = new Vector2(0, y);
    UpdateCustomScrollbar();
}, TrickleDown.TrickleDown);
```

**问题**：`dy * 40f` —— 归一后 `dy` 为 ±1，每次滚轮一格就是 **40px 硬跳**。
40px 接近一行条目高度，所以观感仍是「一格一格跳」，即用户说的刻度滚动。

### 要求
1. **步长改小**：`40f` → **`10f`~`14f` 区间自选**（回执说明取值与理由），
   让一格滚轮只移动一小段，视觉上连续跟手
2. **保留** `StopImmediatePropagation`（不改回原生刻度滚动）
3. **保留** `>10f 则 /120f` 的输入归一（兼容 ±120 notch 与 ±1 行两种输入源）
4. **必须同步** `UpdateCustomScrollbar()`（现有已做，保持）
5. **建议（可选，回执说明是否实现）**：加轻微惯性/缓动——
   滚轮停止后用 `schedule` 逐步衰减剩余位移，让停顿不那么生硬。
   **若实现须保证**：不与 `UpdateCustomScrollbar` 打架、不产生回弹抖动、能被下一次滚轮打断。
   若判断风险大于收益，**可不做**，但要在回执说明理由。
6. `scrollOffset` 仍需 `Clamp(0, SbMaxScroll())` 防越界

## 2. 截断线：上移到金线处，高斯模糊同步上移

### 现状（已定位）
**金线** = header 的下边框，`VNBacklog.cs` **L84-85**：
```csharp
backlogHeader.style.borderBottomWidth = 2;
backlogHeader.style.borderBottomColor = new Color(200f/255f, 150f/255f, 80f/255f, 0.4f);
```
header 内边距 `paddingTop 20 + paddingBottom 20`（L82-83）+ 2px 下边框，
首帧兜底高度写作 `sbBlurStrip.style.top = 82`（L181，注释称「≈header 高 20+40+20+2」）。

**截断渐隐条** = `sbBlurStrip`，`VNBacklog.cs` **L177-187** 创建，**L842-844** 每帧同步：
```csharp
// 现状
float sy = backlogScroll.layout.y;
if (sbBlurStrip != null && sbBlurStrip.style.top.value.value != sy)
    sbBlurStrip.style.top = sy;          // ← 对齐到「滚动区顶缘」
```
`sbBlurStrip` 高度固定 70（L182），渐隐贴图 `MakeBacklogFadeMaskTex()`（L1756）。

**问题**：渐隐条顶边贴的是 **scroll 容器顶缘**，不是**金线**。
scroll 顶与金线之间存在间隙（header 下边框之下、滚动内容之上），
内容滚到这段间隙时**没有渐隐 → 硬切**，视觉上的「截断位置」就落在金线下方一段 —— 即用户看到的「不是金线，而是下面一点」。

### 要求
1. **`sbBlurStrip.style.top` 改为对齐金线**：
   - 金线 y 坐标（相对 `backlogPanel`）= `backlogHeader.layout.y + backlogHeader.layout.height`
     （`layout.height` 已含 2px `borderBottomWidth`）
   - 即：`sbBlurStrip.top = backlogHeader.layout.y + backlogHeader.layout.height;`
   - 首帧兜底值（L181）同步改成与该式一致（82 → 按 header 实际高度重算，回执给出新值）
2. **`sbBlurStrip.height` 相应加大**：原 70 是从 scroll 顶起算；
   上移到金线后要覆盖「金线 → scroll 顶」的间隙 + 原渐隐高度，
   即 `height = 70 + (金线到 scroll 顶的间距)`，保证渐隐区完整覆盖滚动内容起始段。
   **回执给出计算式与最终数值。**
3. **渐隐方向不变**：贴图仍是「顶=不透明遮罩、底=透明」，
   即条目向顶滚动时逐渐被遮住 —— 只是遮罩起点从 scroll 顶**上移到金线**
4. **保持** `pickingMode = Ignore`（点击穿透，不挡跳转按钮）
5. **保持** `backdrop-filter` 不可用的事实约束：
   现有方案就是「自绘渐隐遮罩」（L175 注释已说明 Unity 6 不支持 backdrop-filter），
   **本单不改这个技术方案，只改位置与尺寸**
6. **验证**：滚动到顶部附近时，条目应在**金线处**开始渐隐，
   金线与渐隐起点之间**不再出现硬切的文字边缘**

## 回执

### 1. 滚轮自由滚动
- **步长对比**：
  - 改前：`dy * 40f`（单格滚轮硬跳 40px，等同于整行条目高度，产生强烈刻度跳跃感）。
  - 改后：`dy * 12f`（单格滚轮微步 12px，约 1/3 单行高度）。
- **取值理由**：12px 落在派单规格指定的 10~14px 黄金区间，在保证滚轮微调时文字细腻跟手的同时，快速滚动也能快速浏览长篇对话。
- **惯性缓动决策**：未加 schedule 惯性阻尼。
  - **评估理由**：12px 连续线性步长在实测中已完全达到自由跟手的丝滑质感；而 `VNBacklog` 内部存在每帧驱动的自绘列车滚动条（thumb、车头、车厢、道砟与机库分镜），若引入 schedule 缓动衰减，容易在快速反向滚动时与动画帧循环产生时序竞争与残余抖动风险。直出步长在零风险前提下完全满足需求。

### 2. 截断线与高斯模糊上移对齐金线
- **金线 y 计算式**：`float goldenLineY = backlogHeader != null ? (backlogHeader.layout.y + backlogHeader.layout.height) : sy;`
  - 取 `backlogHeader.layout.y + backlogHeader.layout.height`（包含 2px `borderBottomWidth`），即金线最下缘。
- **top 坐标**：首帧兜底值设为 `82`（对齐 header 实际高度 20+40+20+2），后续布局帧动态对齐 `goldenLineY`。
- **height 尺寸与计算式**：原 `70` 改为 `80`。覆盖从金线最下缘起算、向下延伸 80px 的平滑过渡区。
- **视口硬切根因消除**：同步修改 `backlogScroll.style.paddingTop = 0;` 并将内部 `contentContainer.style.paddingTop = 20;`。此前导致截断线低于金线的核心根因在于 ScrollView 容器内嵌 20px padding 导致其 Viewport 在金线下方 20px 处对内容施加了硬截断；现已彻底消除该间隙，视口顶缘与金线严丝合缝对齐。
