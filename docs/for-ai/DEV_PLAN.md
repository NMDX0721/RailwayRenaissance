# 铁路复兴：沙能冲击 — 并行开发计划

> 本计划定义"文书助手"和"编码助手"的并行工作流。  
> 原则：文档先行，代码跟上。文档是编码的基石，编码是文档的验证。

---

## 一、总体思路

### 两个角色
| 角色 | 职责 | 工作内容 |
|------|------|----------|
| **文书助手** 🖋️ | 文档建设 + 规划 + 协调 | 项目总览、代码地图、设计文档重写、AGENTS.md 维护 |
| **编码助手** 💻 | 代码实现 + 重构 + 玩法扩展 | 按文档优先级实现 P0/P1/P2 任务 |

### 工作流循环
```
文书助手：理解项目 → 写文档 → 定优先级 → 拆任务
                              ↓
编码助手：读文档 → 执行任务 → 验证 → 更新文档
                              ↓
文书助手：审核完成 → 更新文档 → 下个循环
```

### 分支策略
- 文档改动在 `main` 分支直接提交（非破坏性）
- 代码改动在 `feat/*` 分支开发，完成后 squash 合并到 `main`

```
P0.1 → P0.2 → P0.3 → P1.1 → P1.2 → P1.3 → P2.1 → P2.2 → P2.3 → P3.*
  │       │       │        │       │       │       │       │       │
```

## 六、Git 提交规范

```
commit 格式: 类型: 内容

类型:
  feat:    新功能
  fix:     修 bug
  refactor: 重构
  docs:    文档
  style:   代码格式
  chore:   杂项

示例:
  feat: 实现政治压力趋势线
  refactor: 拆分LoginManager为LoginUI+LoginAuth
  docs: 更新CODE_MAP添加科技树系统
```
