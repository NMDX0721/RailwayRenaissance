# 驾驶辅助角色候选方案

日期：2026-10-21。状态：讨论稿，尚未确认角色定名、外形、功能范围；未实现。

## 用户提出的方向

- 简单上手模式由 Q 版小黄鼠协助执行部分驾驶台操作。
- 岁月作为无实体 AI，可考虑通过全息呈现进行提醒、指导，或协助操作。
- 林彪悍需要角色建模，但留待后续。

## 现有设定依据

`参考资料/设定/角色设定.md` 的岁月章节已规定：纯数字意识、可全息陪伴、可接管电子设备，但不能直接搬动物品或开门；离线能力受局域网覆盖限制。驾驶辅助应沿用此边界。车辆设定中“本体在车内”的旧表述与无固定物理载体存在冲突，本提案不沿用该说法。

## 建议分工（待确认）

- 岁月负责状态解读、原因解释、步骤提示与受委托的电子操作；驾驶台侧面的小型投影终端作为表现入口，语音与屏幕可独立使用。投影不具有施力能力，不遮挡线路和仪表。
- 小黄鼠作为有实体的操作伙伴，承担玩家委托的局部机械操作。具体物种、尺寸和是否配辅助机构尚未决定；不能默认普通小鼠能推动重型闸把。
- 玩家保留行车意图、牵引与制动等核心决策，可随时取消委托或接管；不默认启用完全自动驾驶。
- 柴油机车只允许接入已具备传感器、控制接口和执行机构的设备；未来电力机车也按实际接口开放能力，不因动力类型直接获得全车控制。

## 后端约束（后续实现要求）

玩家、角色辅助与自动流程使用同一操作命令入口及联锁校验；辅助模式减少操作负担，保留同一套物理模拟。提示、待执行、执行完成和失败应分别反馈，不能以角色动画代替实际状态变更。角色知识或对话模型只提出动作意图，由确定性的控制层核验和执行，不直接写模拟状态。

可考虑分别开关步骤引导、重复操作协助与角色显示。先做一次冷启动或停机流程示范，再评估扩展；暂不把整个驾驶自动化列为既定需求。

2026-10-21补充：用户要求驾驶数据记录、结束回顾与生涯累计。辅助动作必须记录来源及委托/接管时间，供回顾解释和按辅助条件统计；见[驾驶记录与生涯系统](../../参考资料/系统/驾驶记录与生涯系统.md)。

## 后续角色建模

林彪悍建模延后；届时依据现有角色服装设定，校核座姿、驾驶视点、手部触及范围与驾驶室净空。当前不新增角色模型。
