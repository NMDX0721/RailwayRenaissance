# 探索场景：室内场景、设备交互与 HUD 设计（2026-11-14）

> 分工：逻辑、框架、交互、UI 由 Claude 做；**图形（名牌、室内家具/设备的位图、标牌）后续交给 GPT**，依据本文的元素清单与草图出图。美术规格见 `Assets/Resources/Art/EXPLORE_ASSET_SPEC.md`，口径见 `UI_PAPER_DESIGN_SYSTEM.md` §7。

## 1. 核心原则
1. 像星露谷：**进门=换场景**。室外地图是「站区」，每栋建筑有自己的室内小地图（有墙、地板、家具、设备、NPC），门口是出入口。
2. **经营功能不再是菜单项，而是场景里的设备/家具**。走到设备旁出现提示，按 E/点击才打开对应的单页面板。没有“前往”栏、没有全局经营按钮。
3. 室外只留：站台设备（检票机、信号机、道岔扳手等）、道口、茶摊、公告栏——都是**就地交互物**。
4. 随身 UI 只保留：打卡机工牌卡（身份/时间/日程/资金/信任 + 地图、系统）、物品栏、精力条、交互提示。

## 2. 室内场景框架（数据结构）
每个区域 `Area { id, w, h, grid[], spots[], npcs[], spawn, exits[] }`：室外=`outdoor`，室内=`hall/dispatch/waiting/garage/tea/dorm/office`。
- 进门：走到门格 `D` → 淡出 0.2s → 载入室内区域，玩家落在室内门口；出门反向。
- 室内网格沿用 T=32、AABB 碰撞、A*、WASD/摇杆/点击；摄像机在室内按房间大小居中（房间小于视口时居中并画墙外暗角）。
- 小地图/地图面板：室外显示站区；室内显示当前房间平面图。
- 时间：进出门不耗时；设备交互按 `cost` 分钟计时。

## 3. 各建筑草图与元素
符号：`#` 墙 `D` 门 `.` 地板 `[ ]` 设备（可交互）`s` 沙发 `t` 桌 `n` NPC `*` 装饰

### 3.1 站台（室外就地设备）
```
 ┌──────────── 站台 ─────────────────────────────┐
 [检票机]   [时刻表牌]   [信号机]      [道岔扳手]   [广播台]
   闸机×2     今日班次      红/绿灯      手动扳道      播报/通知
 长椅 ═══ 候车线(黄) ══════════ 耕牛(停靠 1 道) ═══
```
| 设备 | 作用（改哪些既有数据） |
|---|---|
| 检票机 | 当日客流相关：查看/加快检票（影响预期客流小幅度、耗时） |
| 时刻表牌 | 只读：今日发车方案摘要，可跳到调度室 |
| 信号机 | 巡检小活动：成功→口碑+；失败→车况/时间代价 |
| 道岔扳手 | 线路巡检：线路状态定性反馈（不外显数值） |
| 广播台 | 发布通知：消耗时间，小幅口碑 |
| 耕牛车头 | 查看车况；与车库联动 |

### 3.2 调度室（经营：发车方案 / 经营策略）
```
 ########################
 # [挂钟] [线路大屏]  *窗 #
 #  t┌调度台┐  [电台]     #
 #   │ 班次表 │ [策略板]   #
 #  s沙发  *茶几  n赵师傅  #
 ####### D ################
```
- 调度台 → 发车方案页；策略板 → 经营策略页；线路大屏 → 只读线路图；电台 → 与沙能动向/上级通告（定性）；沙发+茶几 = 休憩点（回复少量精力）；赵师傅 NPC。

### 3.3 站务大厅（订单）
```
 ##########################
 # [委托公告板]  [售票窗口×2]  #
 # *长椅*长椅    n李阿姨(站务) #
 # [失物招领]  [自动售票机]    #
 ########### D ##############
```
- 委托公告板 → 在办订单（接取/交付）；售票窗口 → 票务小活动（车票物品、客流）；自动售票机/失物招领：杂项交互与剧情碎片。

### 3.4 候车室
```
 #######################
 # 长椅×3  [饮水机] [电视] #
 # n乘客  *行李   [信息屏] #
 ######### D #############
```
- 与乘客聊天（口碑，每天一次，已有）；电视=新闻/沙能舆情（定性）；信息屏=只读客流。

### 3.5 车库（人员）
```
 ##############################
 # [工具墙] [工作台] 机车位(坑道) #
 # [更衣柜]  [休息间 床×2]  n张工 #
 ######## D #####################
```
- 更衣柜/休息间 → 人员页（安排休息）；工作台 → 培训；工具墙 → 取工具（物品栏）；机车位 → 检修小活动（车况）。

### 3.6 宿舍/办公室（财务 + 结束一天）
```
 ####################
 # [账房桌] [保险柜]   #
 # [书架]   [床] *台灯 #
 ###### D #############
```
- 账房桌 → 资金趋势/日报；保险柜 → 小额资金调拨（后续）；**床 → 结束一天并弹日报**。

### 3.7 茶摊、公告栏、道口（室外）
茶摊：茶嫂 NPC + 茶叶物品；公告栏（室外）：沙能动向/公关；道口：巡检。

## 6. 寻路审查结论（`ExploreMapView`）
结论：A* 本身正确（8 向、不切角、可达性检查），但**以前的实现有 5 个会影响手感的问题**：
1. 每走到一个路点就停一帧（`Step(zero)`）→ 走路动画每格抖一次。**已修**：同帧连续越过路点。
2. 路径沿格子中心 8 向锯齿、贴墙。**已修**：加入 string-pulling 拉直，用玩家碰撞盒做视线检测。
3. 卡住后重寻路可无限循环。**已修**：最多 3 次，失败提示“被挡住了”。
4. 路径从起点格中心开始而非玩家位置。**已修**：以玩家位置为起点。
5. open 表线性扫描，`open.Contains` 为 O(n)。**已修（2026-11-17）**：抽出 `ExplorePathfinding`（二叉堆 A*，惰性删除，与视图解耦；`NearestWalkable` 同环取欧氏最近）。
**已处理（2026-11-17）**：NPC 是实体（移动碰撞 + 寻路绕开，已重叠时放行避免卡死）；点击建筑墙体/屋顶 = 走到最近的门并进入；跨区域寻路 `RouteAcrossAreas`（先出门/先进门，切换后继续，手动输入或新点击会取消排队）；地图面板点击在室内时先走出门。评审 `ExploreReview` 有对应断言，`SimulateAutoWalk` 可在批处理里推进自动寻路。
仍未处理：NPC 日程/移动；多 NPC 互相避让；脚步声与冲刺拖影。
