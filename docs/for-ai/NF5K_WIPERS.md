# NF-5K 双雨刷批次

2026-10-24：已完成首轮实体驱动、双速、正常关机回位、断电冻结及上下文控制；动态天气/日照仍按此前安排暂缓。

## 当前实现

`CabWiperMotion`独立管理0/低/高及完整往返相位。候选低速36次/分钟、高速60次/分钟，位移用余弦往返使换向平滑。变速不重置相位；正常关机以低速走完剩余周期到停放位。无电立即冻结原位，恢复供电后继续已选模式或剩余回位。拒绝NaN/Infinity/非正时间步，单步最多0.25秒。

`CabWiperSystem`读取显式正常/备用供电状态，驱动两套镜像平行连杆。各自主/从轴相隔35 mm，两臂保持460 mm，载架与440 mm胶条保持竖向姿态；不是把刮片和主臂一起刚性转动。胶条后面贴合前窗局部z=0.010 m，摆角±50°，使用200步完整周期检查胶条网格不越过预留窗框范围。

`NF5KWiperSetup`替换旧静态外侧杆件，保留前窗与车体；补双轴密封座、贯穿轴、内侧安装板、减速器/电机外罩、可拆盖、四颗带凹槽的螺丝、设备位号W1/W2及受约束走线。参数与罩壳为原创候选装配，未模拟内部齿轮、密封力或结构强度。

驱动线束下端回接带金属法兰的入墙护套，避免留下悬空断头；检查竖向走线、回接段、护套与法兰的连接包络。供电引用支持延后获取：基础生成器先装饰件后装灯光供电组件，不会因此留下永久空引用。

台面一组三档选择器同步控制两侧，明确“关 OFF / 低 LOW / 高 HIGH”，复用玩家主交互键，无新增快捷键。控制板位于车体局部(0.36,0.8405,0.29)m，3 mm薄板、四角螺丝与低矮旋钮。初始(0.16,0.8405,0.23)m与琴键组重叠，已由出图发现并移位；新检查以驾驶台实际硬件网格的局部包围盒判断相邻净空，不用放大的交互碰撞盒判断实物穿模，也不把TextMesh标注当实体。

`SelectMode`限制近距操作，主开关可在断电时预选。`Motion`为诊断/验收接口，玩家、教程或辅助操作须走`SelectMode`。禁用组件恢复关闭与停放位。可选`BindLegacy`显式连接旧`Cab3DSceneController`：旧开关开启选择低速，关闭触发回位；实体选择高速时同步布尔状态不会降回低速。未绑定的旧演示窗口不会自动被全局搜索接管。

部件进入CabInteriorBlockout、CabDaylightReview、CabSimulationReview和CabRailMotionReview四份检查场景；渲染、旧天气入口与已有场景之间不假定自动全局接线。

## 首轮API纠错（保留记录）

`Cab3DSceneController.ToggleWipers()`原先直接翻转`IsRaining`，等于“按雨刷就切换天气”。现在只切换独立`WipersOn`；`SetWipers(bool)`返回是否实际改变，并仅在变化时发出`WiperStateChanged`。`ForceWeather`只管雨，不覆盖雨刷选择。现有两个UI入口仍调用同一个ToggleWipers，不另造第二条控制路径。

`NF5KWiperStateReview`在不生成旧程序化场景的临时组件上检查晴天开刷不下雨、下雨不改选档、停刷不停止雨、重复设值不重复发事件，纳入原驾驶Play回归。最初这一步只纠正状态API；实体动作现由上方所述的新系统补齐，状态API验收仍独立保留。

首轮验证：`tools/compile/cab_fan_v33_stdout.log`退出0，`NF5K_WIPER_STATE_OK`通过，原驾驶回归保留。

## 初始源码装配基准（历史）

`NF5KReferenceBody.Build`已有两套外侧结构：主轴、弹簧主臂、平行连杆、刮片背骨、胶条及接头。两扇前窗各约1.045×0.72 m、倾角8°。模型坐标为构图候选，不是DF4或任何厂家的测绘尺寸。

当前主轴局部位置为(x=0.735或-0.375,y=1.19,z=-0.676)，主臂接点相对轴为(-0.10,+0.36,+0.05) m，平行杆端点横向错开25 mm。下一步必须复核刮片载架是否真正连接到两根杆、轴的内外穿墙路径及窗框净空，不能只把整套雨刷绕一个点转动就称作完整平行四边形机构。

## 剩余边界

清洗泵、雨滴/水膜、干湿摩擦、内部齿轮载荷、独立左右分档、真实电流和全局存档均未实现。Android设备性能及与未来天气的湿度/附着联动需要另验，不由当前几何与供电检查推断完成。
