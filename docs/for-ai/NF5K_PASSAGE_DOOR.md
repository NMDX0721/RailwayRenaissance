## 行为与装配

`CabPassageDoor` 独立管理隔门 0–90° 开合，沿车体局部 +Y 轴旋转，向驾驶室打开。`OpenFraction` 表示位置，`SetOpen` 提供检查角度，`Toggle` 执行开关。沿用侧门的即时状态切换方式，尚未实现缓动、锁闩、门阻力或人员阻挡时的实时防夹。

`CabContextInteraction` 从所在根对象收集隔门碰撞体，将门板/玻璃/把手命中解析到隔门组件，提供中文“打开客舱隔门 / 关闭客舱隔门”，沿用已有交互距离、主键绑定和 UI 遮挡路径。不触发 ATO 人工接管，不更改驾驶控制或四侧门数量约束。没有自由行走控制器的场景仍需已有视角工具或编辑器移动到门前，本轮不能声称玩家已能完整步行穿车。

原几何开口保持 0.620m。铰轴从 X=-0.300 调整到 -0.275m，闭门网格位置保持不变，以留出旋转厚度空间；全开门板占据开口左侧，基础门板对应的剩余横向净距约 0.5625m，**不等于全程人体净距认证**。玻璃补实体 BoxCollider，避免透明上半门可被射线或通行检查穿透。`CabInteriorBlockoutSetup.Build` 同步生成该装配。

## 迁移与验证

`NF5KPassageDoorReview.Batch` 通过 Unity Editor API 迁移四场景、检查后保存并重新加载，再重复检查；不直接编辑场景 YAML。迁移幂等，保留已有子件闭门世界位置。失败在保存前中止当前场景；先前通过的场景不会回滚。

- 扫掠：0–90° 每 1°一个角度，门下板、玻璃和把手的 BoxCollider 对车体内其他非触发 Collider 使用 ComputePenetration；超过 2mm 报错。属于离散角度检查，没有连续碰撞或工程零间隙保证。
- 通行：门全开后，直径 500mm、高 1.75m 胶囊体，在 X=0.03、中心 Y=0.88、Z=1.30–2.50m 每 30mm 一个位置检查。范围只覆盖隔门短通路，不替代座椅/平台/全车动态限界；2mm 为检测阈值。
- 回归：四场景各执行原有 `NF5KDoorReview.Validate`，确认四侧门仍通过原 44 角度扫掠。
- Play：在 CabSimulationReview 中验证玻璃碰撞体解析为隔门目标，通过实际 BuildChoices/ExecuteSelected 分发开关，检查 OpenFraction 变化；不是键盘硬件输入、玩家移动或 UI 点击的完整端到端验收。
- 图像：`tools/cab_reference/passage_door_review/open.png`、`closed.png`，使用临时补光；检查相机参数和临时灯不保存到场景。
