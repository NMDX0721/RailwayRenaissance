# ATO V3 控制核心

研究原型在给定路线和观测初速下，使用前向加速、反向减速速度包络及巡航速度二分构造参考；平稳、省气、准点三模式从九个参数组合中选择参考。控制器每五个物理 Tick 基于观测和已接受命令更新估计，筛选有限候选及三种制动响应情景，再按目标评分。无可行候选时请求零牵引与常用全制动并退出。有限情景不构成形式化安全保证，参考轨迹不保证实际准点。

接口为 `CabAtoControllerV3.Decide`、`AtoV3State` 与 `AtoTrajectoryPlanner`；测试入口 `research/ato-v3/AtoV3.csproj`。V2 和物理内核保留，研究结果及限制见 [实验报告](../research/ato_v3_results.md)。

## 已知缺口：V3 未强制最短制动切换间隔（2026-11-02）

Codex 审查指出 V3 只限制油门增加（25 采样点），没有像 V2 那样限制制动切换。已验证属实：开发场景里制动切换间隔不足 25 采样点，Smooth 模式有 194 次。冻结协议（protocol-v1/v2）记录了 `CabAtoControllerV3.cs` 的哈希，直接改这个文件会让冻结验证和已提交的运行数据失效，所以活动文件保持不变，缺口作为 V3 冻结版的已知限制。

已验证的改法在 `research/ato-v3/followup/V3DwellSoftFilter.patch`（未应用）：第一轮保留 25 采样点最短间隔，仅当没有任何候选满足间隔时才放宽，再不行才干预退出。开发运行结果：Smooth 0 次、AirSaving 2 次、Punctual 3 次（仅在无合规候选时），到达时间与误差基本不变，无干预，`V3_REPLAY_OK`。若不保留第二轮，三种模式都会在途中干预退出，停在站前 19 至 42 m。要采用它，需应用补丁后重新冻结协议和实验。


## PR9 后续修复：驻留前缀预测与检查点（2026-11-02）

以上缺口描述适用于冻结的状态版本1，旧归档及旧运行数据保持原样，不因修复改写。新构造的控制器使用状态版本3，保存LastBrakeSwitch；普通制动切换必须间隔至少25物理Tick。预测候选先执行尚未满足的当前制动驻留前缀，再预测候选动作；驻留期实际输出仍保持当前制动，不能用第二轮软过滤偷偷放宽约束。干预全制动与已到达保持仍独立处理，统计必须区分。

状态版本1恢复后仍按原策略重放，仅服务历史兼容，不能把它标为符合新驻留约束；实验过的状态版本2保留硬过滤语义。旧协议请从原冻结压缩包复跑，不对修改后的活动源码套用旧哈希。版本3需要单独冻结新源码和协议。

Engage先在局部变量中完整创建三个候选控制器，全部成功后再更新活动字段，失败时不留下半创建状态。Restore允许非活动、无V3而有旧V2路线的历史检查点；活动或存在V3数据时仍要求完整V3路线与状态，拒绝发生在物理状态恢复之前。

独立检查覆盖首次未启用、移动建轨迹失败、旧半创建存档、损坏活动存档和失败重启后的控制器状态。使用协议 v2 的已查看初态执行 54 次回归，三模式各 9/9 成功，普通短驻留、干预和越速均为 0，27 对重复的指纹一致。独立项目的四阶段恢复和 30/60/144 FPS 固定 Tick 回放通过。Unity Play 和真实 3D 场景验收待完成。

恢复 V3 状态时，`DecodeCheckpoint` 接受历史版本 1 缺少 `LastBrakeSwitch` 的完整旧字段序列。迁移保留版本 1 和原控制策略。新版存档使用完整字段序列。V3 的停车误差和路线遥测使用实际路线目标，独立于 V2 路线开关。
