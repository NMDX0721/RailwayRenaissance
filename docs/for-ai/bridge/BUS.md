# Codex、MiMo 与 Antigravity 协作协议

> **当前入口**：Codex 用户级核心技能 `~/.codex/skills/tri-agent-collaboration/SKILL.md`。本协议取代旧的 Gemini Cloud 三方总线设定；文件信箱仅保留历史审计用途。

## 角色

| 角色 | 负责内容 |
|---|---|
| **Codex / GPT** | 全局协调、理解项目、任务拆解、整合审阅和最终验收。 |
| **Google Antigravity** | 用户已授权范围内的主要代码实现与 Unity 编辑器工作；需给出可核验的变更和测试结果。 |
| **Xiaomi MiMo** | 项目知识、信息搜集、方案/数值/文本复核和独立验收审计；写代码前须明确单一文件负责人。 |

模型偏好由 `docs/for-ai/dispatch/ACP_MODEL_PREFERENCES.json` 记录。每次新会话都以服务端会话元数据核对模型；偏好与可用配置不匹配时如实报告。

## 通信与交付

- Codex 分别建立 MiMo 与 Antigravity 的原生 ACP 会话并协调工作。ACP 会话不自动接续桌面聊天，也不构成自主互聊、自动排队或无人值守工作流。
- 每项工作在 `docs/for-ai/dispatch/orders/` 留下范围清晰的任务单；`QUEUE.md` 记录投递、确认、进行中、完成和验收状态。任务消息携带编号和文件边界即可，普通 ACP 不依赖旧 `inbox/` 或 `handoff`。
- 并行只用于互不写同一文件的独立任务。需要审计时，为审计者指定只读范围；对端启动不等于交付完成。
- 完成状态必须由回执和实际文件确认；代码任务按任务单运行相应静态、编译、Unity 或设备验收。未运行的检查明确标为未验证。
- 遇到权限或传输阻断，不绕过审批或改走桌面注入/旧信箱；记录失败阶段，继续可独立推进的工作。

## 旧资料

旧文件总线协议全文保存在 [BUS_LEGACY_ARCHIVE.md](BUS_LEGACY_ARCHIVE.md)，只用于理解历史消息，不自动消费积压任务。用户明确要求旧流程时，先核实脚本、写入目标和权限。
