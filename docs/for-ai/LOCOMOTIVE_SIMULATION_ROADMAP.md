# 从单张驾驶台到可驾驶柴油机车与线路

当前车型结构以2026-10-20用户确认优先：NF-5K头车整合驾驶室与客运空间，后隔门通向客室，动力设备需隔离，另一端驾驶室按编组安排。本文下方“机车模块”指动力学/设备逻辑，不等于纯独立机车头。见 [NF-5K头车结构](NF5K_HEADCAR_LAYOUT.md)。

技术对照来源：Open Rails官方物理介绍 https://www.openrails.org/learn/physics/ 及官方文档源码 https://github.com/openrails/openrails/blob/master/Source/Documentation/Manual/physics.rst 支持将牵引、黏着和充排风过程分别建模的路线；Unity6.5 LOD说明 https://docs.unity.com/en-us/engine/6000.5/manual/analysis/graphics-performance-profiling/lod/level-of-detail 用于远景分级策略。当前不引入其代码或额外包，也不以引用说明本项目已达到同样仿真程度。

2026-10-20。用户确认最终范围包含完整驾驶室、拟真机车后端、轨道与窗外景色；分阶段实现，不把目前单台组件预制体当成完整机车。

## 当前实情

- 主驾驶台已有统一装配，仪表部分读取CabEngineState；启动组件本轮安装并接鼠标射线。其他手轮、大小闸、琴键仍有未接操作。
- CabEngineState仍是简化演示：固定列车质量/阻力、档位牵引、转速目标、水温目标以及风压趋近。没有完整机车/车辆/线路求解器。
- Cab3DSceneController已有道床、双轨、65根枕木、立杆、景物、远山、车站、信号及天气表现，主要按速度循环移动；不是已实现的曲线坡道线路，也没有与运行里程绑定的完整地理场景。
- 现有轨道注释写1.435 m轨距，但矩形钢轨中心±0.717 m、宽0.09 m，不能直接当内侧工作面轨距正确。后续轨道截面必须以轨头内侧工作面定义轨距，不能只按中心距验收。

## 1. 先做一段可验收的驾驶切片

顺序：启动组件实装与鼠标动作 → 速度/油门/换向/大小闸/撒砂/鸣笛操作 → 油压/供电/热管理/空气制动最低闭环 → 完整驾驶室与可行驶测试线路。每一步都要有输入、真实状态、反馈和复现验收，不能只让指针动。

切片先只支持一种虚构改装柴油电传动机车、一种制动配置和一个短编组，跑通冷车启动、牵引加速、惰行、停车、停机以及一个冷却或制动故障。长度/坡度/编组参数待路线数据选型，不在此虚构真实车性能。

## 2. 完整驾驶室美术

在现有台面坐标系外建立CabInteriorRoot，以地板/司机眼点为共同基准；机车前方、地板高度、车体中心线与模型单位统一。

- 壳体：前风挡与边框、侧窗/门、后隔墙、顶棚、地板及维修盖；先用灰模验收空间与视线，再做旧漆和损耗。
- 乘务空间：可调司机座椅、副司机位、脚踏/警惕件、扶手、工具/灭火器安装处。座位调节范围与触达要结合角色体型验证，不凭截图宣称人体工学合格。
- 外观与交互：玻璃、雨刷/除雾、车灯/室内灯、开门开窗、镜面/遮阳板与声音遮挡。
- 朝鲜元素：小型国旗、车号/所属/检修牌、经核对的朝鲜文铭牌、纸质行车记录。选择固定地点安装，避开风挡主视野、灯光指示及操纵轨迹；不用未经核验的真实单位铭牌冒充考证。
- 输出分独立壳体/可动门窗/座椅/雨刷/可拆设备，保留枢轴。不能把整间驾驶室烘成不可操作的一块网格。

## 3. 后端：可标定模型比堆复杂公式重要

先以确定性的低阶物理模型建立统一状态快照，组件只读/发命令。固定仿真步长与渲染帧解耦，使用SI量纲并明确单位转换；不能在两个MonoBehaviour里各积分一次，也不能按帧率改变制动效果。

| 模块 | 最小模型与实际影响 | 验收依据 |
|---|---|---|
| 柴油机/调速器 | 启动阶段、曲轴惯量、转矩-转速/燃油曲线、负载调节 | 启动时间/怠速与负载转速、燃油量守恒 |
| 发电/牵引电路 | 实际电压电流与效率、恒流/恒功率区、限流和接触器状态 | 轮周牵引力-速度曲线、功率平衡；安培不能直接当功率 |
| 黏着/轮轨 | 法向载荷、黏着上限、滑移、湿轨/撒砂影响 | 起动牵引、空转和保护的可复现触发；不盲设牵引力 |
| 纵向运动 | 单车质量、回转质量、滚动/空气/坡道/曲线阻力 | 加速/惰行曲线、坡道平衡；F=ma不能代替所有阻力 |
| 空气制动 | 压缩机/总风、均衡风缸/列车管、分配阀/副风缸/制动缸、传播延迟/泄漏 | 充排风过程与停距；大小闸、单缓、停车制动分开 |
| 热与润滑 | 机体/水/油热容、泵/节温器/风扇、余热、油压与黏度/转速 | 冷启动/热浸/高负载、冷却故障；见热管理设计 |
| 电源/启动 | 蓄电池荷电量/内阻、起动机负载、发电充电、使能与保护 | 起动压降、不能反复无限免费启动 |
| 编组/连接器 | 第一阶段刚性短编组，后续逐车纵向运动与车钩缓冲器 | 制动传播、纵向冲动与质量一致 |
| 信号/保护 | 线路授权、闭塞/道岔、速度限制、警惕、确认及介入 | 信号由运行状态决定，不按距下站一个数自动变色 |

高保真不等于每个零件都做刚体接触。车辆沿线路约束运行，先做可标定的纵向动力学；转向架摇摆/车体振动先采用受轨道扰动驱动的低阶模型。仅在需要脱轨/碰撞等玩法时增加对应求解，避免用未标定的Unity刚体车轮冒充铁路动力学。

真实车型数据需有出处和单位：额定功率、转速、牵引力曲线、质量、传动效率、制动能力、风缸容积、燃耗与散热。暂无数据的参数明确标“游戏标定”，不输出伪精确性能承诺。用记录/回放、守恒检查与参考曲线误差验证“拟真”，而非只凭画面。

## 4. 轨道与线路是共同坐标，不是循环背景

建立RouteGraph，包含区间、节点/道岔、方向、轨距、里程、平面曲线/缓和段、坡度/竖曲线、超高、限速、站点、信号和占用。运行状态使用边ID+s里程+方向；世界姿态与坡道阻力都由同一个线路采样器输出。

从同一采样结果生成轨头截面双轨、轨枕/扣件、道砟/路基、桥隧和路旁标志；按弧长布置枕木，避免曲线内外间距错误。道岔有拓扑与锁闭状态，不能只画两根分叉轨。初期无需无限世界，先验收一段直线、曲线、坡段、道岔/停车点。

线路身份须对应存档种子，静态拓扑与坡度不能每帧变动；不能只换景物而让站间距离/订单距离和物理里程脱节。

## 5. 窗外景色与图中场景

沿线路分区块加载地形、道路/河流、聚落/厂矿/车站、植被和电杆；优先手工布置运行相关的车站、信号、限界与道岔，再用种子规则补普通景物，不能把重要运营设施纯随机散落。

照片用来提取地形关系、建筑尺度、植被与时代材质，不能从单张照片恢复未知背面的真实几何。既有低分辨率窗外渲染可保留为美术策略；驾驶室资产细节与项目16-bit经营/VN画面通过统一色调和可选渲染输出协调，不擅自把整个项目改成另一套写实游戏。

采用近/中/远景层级、实例化/对象池、按线路区块流式加载；长距离计算用高精度里程，Unity展示局部坐标并按需迁移原点。驾驶室不能随原点移动抖动，灯光、雨、音源、碰撞与信号引用一起迁移。渲染可视距离与安全/制动计算距离分开，远处未加载网格不等于那里没有列车或红灯。

## 6. 项目接线与交付边界

创世核负责新开局种子及初值抖动，运行中的设备参数不每帧随机；旧档迁移有版本与兜底。燃料/维护费用只由一处核算，驾驶仿真与经营日结不能重复扣同一份燃料。钱/信任以外的政治压力与老化仍遵守项目定性外显规则，不能借诊断面板泄漏这些数值。

近期验收：同种子/同命令回放一致；不同帧率不改变停距；启动缺条件拒绝、热故障可观测、油温与油压不混用、线路坡度真正影响牵引/制动、站点与信号共享里程、读档不重置热态/风压。每阶段保存性能与功能证据，再扩到完整驾驶室和长线路。

本文件是实施路线，不表示上述系统已完成；本轮实际编码仅启动组件实装、鼠标射线动作与既有发动机状态接线。
