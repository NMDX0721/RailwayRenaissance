# 自动驾驶研究在 RailwayRenaissance 中的应用与改进方案

2026-10-23。性质：源码定向审查与后续设计，不是已实现的ATO或实验结果。

## 1. 推荐定位

系统展示目标是“单车单区间的自动运行原型”：人工完成钥匙、主控和启动准备，系统在既有联锁允许后完成牵引、惰行、限速跟踪与定点停车，玩家随时可接管。科研主问题仍收敛在**模型失配下的停车精度、越界和操作平顺性**；全程运行是应用场景，不能同时承诺完整信号闭塞、多车调度或真实线路安全认证。

题目建议：《面向列车驾驶仿真的自适应预测控制研究——以速度跟踪与定点停车为例》。若进度不足，论文聚焦停车，标题同步收窄。预测控制、自适应估计、多情景比较、滞回均有成熟先例，不以高级名称代替创新性证据。

## 3. 一套控制器、两种运行环境

建议的结构（均待开发）：

1. **路线任务**：给出目标里程、分段限速、纵坡、允许公开的线路信息及运行终点。目标不采用构造器随机StopPositionM，明确使用准备后位置+任务距离，并记入manifest。路线任务属于独立实验输入，不写入玩家存档，不替代游戏种子初始化机制。
2. **观测接口**：只提供允许控制器使用的速度、位置、压力等观测。真实质量、未知黏着、故障真值只供实验环境使用，不能从Model.State或Input反向泄漏给候选控制器。
3. **运行状态机**：待准备→可发车→牵引/惰行→进站制动→停稳保持；另有人工接管、规划超时和异常回退。首版发动机启动由玩家完成，不把操纵程序自动化混入控制精度研究。
4. **控制核心**：读取观测和公开路线信息，输出命令意图。独立.NET运行器与Unity适配层复用同一控制核心；控制器不引用Unity、PlayerPrefs或GameData。
5. **命令仲裁**：手动/自动只有一个普通命令所有者；人工接管及紧急指令优先，接管后禁止下一自动Tick重新覆盖。自动目标档位经现有Set接口执行；日志分别记录请求、接受/拒绝与实际内核输入。
6. **被控内核与回放**：内核仍为唯一状态写入者。每5个0.02秒步触发一次控制更新（初拟10Hz），轨迹记录实际生效输入。不同渲染FPS不得改变控制Tick序列。

独立运行器先验证；Unity首版只进入单独研究场景，由Editor脚本生成，保留原检查场景，不直接编辑unity YAML。现有轨道循迹可用于展示，但不能提供模型之外的性能证据。正式接入有代码改动时同步CODE_MAP、接口说明与验证记录。

## 4. 高级算法怎样做得具体、可算、可证伪

### 4.1 基线不能省

- 固定制动点/固定常用档，另比较两种常用档中的最佳开发集基线。
- 速度/距离反馈规则或经典制动距离估算，使用相同观测与动作权限。
- 固定参数预测控制：作为判断“在线估计是否有用”的强基线。

### 4.2 先做有限候选序列的预测控制

停车阶段仅考虑释放、常用2、常用3。将预测时域划为3个动作块，则最多3^3=27个序列；不要按每个0.1秒决策点无限展开，10个控制点已是59049个序列。候选数、预测时域、块长度必须作为参数公开并测实际计算耗时。

预测状态至少保留速度、位置和制动响应状态；短时域不能仅奖励当下误差，还需终端停车距离/速度项，避免最后几秒才发现无法停车。终端近似并不构成可停车性的数学保证。代价可同时包含速度跟踪、终端停车误差、动作切换与约束违反；不同量纲需归一化，权重只在开发集选定。

只执行第一块的首个控制周期，再根据新观测重算。不得把一段完整规划直接视作实际轨迹，也不能通过直接改刹车缸压力制造控制权限。候选全部不满足约束时必须返回“无可行解”，由独立回退规则处理并计入失败/干预，不能默选违规最少者却记成正常成功。

### 4.3 在线估计先估“有效制动响应”，不盲目辨识所有参数

只估1–2个可从数据识别的量，例如有效减速度修正、建压响应时间；先用有界低通估计，确有必要再考虑递推最小二乘。车重、坡度、黏着和气压效应可能互相混淆，单靠速度变化不能承诺同时准确识别。

有足够制动激励、持续时间和有效速度才更新；滑行、反向、接近零速及异常观测时冻结，估计越界回退名义参数。记录预测误差、估计轨迹和更新条件。扰动真值不参与估计器初始化或在线选择。

### 4.4 多情景预测作为第二层升级

对同一候选在公开预设的名义/弱制动/慢响应等假设下评分，使用最坏情景或显式风险惩罚。27候选×3情景是81条预测轨迹，还需计每条内核步数，不能只看81就断言实时可用。

该方法只能称有限情景防御性处理，不是已证明鲁棒MPC或工业ATP。不得把仿真器真实未知参数直接设置到预测副本，否则形成“知道答案”的循环验证。应包含未用于调参的响应速率和观测延迟条件。

## 5. 真正值得优先改进的点

| 优先级 | 改进 | 为什么比堆功能更重要 | 最小验收 |
|---|---|---|---|
| P0 | 保留有符号目标距离及统一到站判定 | 避免越站也获成功 | 目标前、目标后、过零溜车及停稳窗口反例 |
| P0 | 控制Tick、单一命令所有权、请求/实际输入日志 | 防止帧率和手动冲突伪造算法差异 | 同输入30/60/144FPS控制序列及轨迹一致；接管后一自动周期无覆盖 |
| P0 | 冻结配置/初态/环境，恢复后参数不变 | 避免适配层把实验工况改写 | 黏着0.30等完整检查点恢复后若干步保持一致 |
| P0 | 将现有距离灯色与任务限速/授权区分 | 避免研究把显示提示当完整信号保护 | 临近停车目标不与伪红灯产生规则冲突；不宣称闭塞完成 |
| P1 | 预测模型与真实模拟环境分离 | 防止真值泄漏和完全相同模型自证 | 候选只收到规定观测，测试模型失配且保留原始工况 |
| P1 | 计算预算、超时和不可行处理 | 高级算法不能只算得好却算不完 | 记录每周期耗时、P95/最大值、超时与回退次数；不宣称硬实时保证 |
| P1 | 约束与代价的消融 | 证明是哪部分带来改善 | 固定MPC、加估计、加多情景分别比较，等调参预算 |
| P1 | 调控理由与回放 | 帮学生解释、玩家理解和排错 | 显示真实状态摘要如“接近停车点/气压未恢复”，与命令记录对应，不伪造自然语言推理 |
| P2 | 节能、时刻表、多车与经济联动 | 有应用价值但增大归因难度 | 停车和速度跟踪通过后另立实验，不抢本次申报主体时间 |

所谓“高质量”最终应体现为控制有效、故障可见、数据可复现、玩家能接管。界面美观或模型细致不替代这四点。

## 6. 可交付闭环及时间边界

必须完成：冻结被控模型与实验协议；两种透明基线；固定参数预测控制；停车与速度跟踪流水；单一目标的误差/越界/失败/切换/计算耗时比较；独立运行可复现。

优先升级：在线估计与消融。计算量允许才加多情景。游戏演示复用同一控制器，展示起步—跟踪限速—停车—接管；若整段运行影响科研进度，先做准备完成后的进站停车演示。

## 7. 先行工作与AI辅助

本次打开并核查：[吴鹏等，2013，《基于预测控制的列车精确停车算法》期刊摘要](https://www.joca.cn/EN/Y2013/V33/I12/3600)，已涉及制动延迟、速度/距离目标和约束；[Farooqi、Fagiano、Colaneri，2018，Efficient Train Operation via Shrinking Horizon Parametrized Predictive Control，作者公开稿](https://fagiano.faculty.polimi.it/docs/papers/NMPC_train_2018.pdf)，涉及离散运行模式、限速与预测控制。后者采用的特定参数化/收缩时域方法不能被本计划的简单候选枚举冒称复现，其收敛结论也不能借用。
