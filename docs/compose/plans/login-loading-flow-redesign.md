# 登录/加载流程重构规划

> 版本：v1.0
> 日期：2026-09-18
> 状态：规划中（不改动代码）
> 前置：平板桌面液态玻璃重构完成、App矩阵对齐

---

## 一、现状分析

### 1.1 当前场景流转

```
Login场景(2344行) → TitleScreen场景(540行) → NewGameSetupUI → VN_Test → StationSlice_V1
```

| 组件 | 行数 | 功能 | 问题 |
|------|------|------|------|
| LoginManager.cs | 2344 | 登录/注册/自动登录 | 密码明文、本地auth.json、无网络验证、与平板账号体系冲突 |
| AutoLoginUI.cs | 241 | 9阶段模拟加载动画 | 假加载（无真实网络请求）、浪费开发资源 |
| TitleScreen.cs | 540 | 标题界面（新游戏/继续/设置/退出） | 与平板桌面完全独立、重复功能 |
| NewGameSetupUI.cs | 417 | 难度选择（4档+自定义） | 独立于平板系统、体验割裂 |
| GameMainUI.cs | 1752 | 平板桌面 | 不在标题流程中、新玩家看不到 |

### 1.2 核心矛盾

1. **登录系统与平板账号冲突**：设计决定登录合并到平板的"小米账号"，但现有LoginManager是独立的登录系统
2. **标题界面与平板桌面重复**：TitleScreen的功能（新游戏/继续/设置/退出）在平板桌面的App中都能实现
3. **新玩家体验割裂**：新玩家需要经历 Login→注册→假加载→标题→难度选择→序章 才能开始玩，流程太长
4. **加载流程虚假**：AutoLoginUI的9阶段加载是假的，没有真实网络请求

**平板桌面 = 游戏的唯一入口**

就像真实的平板设备一样：
- 开机 → 锁屏 → 解锁 → 桌面
- 在桌面上操作一切（新游戏/继续/设置/账号）

## 三、小米账号系统

### 3.1 设计方案

**不实现真实网络账号系统**。小米账号是叙事元素，不是功能系统。

| 维度 | 方案 |
|------|------|
| 存储 | 本地PlayerPrefs（与现有一致） |
| 登录 | 平板"设置"→"小米账号"→输入用户名 |
| 注册 | 首次开机向导中设置用户名 |
| 数据 | 用户名 + 头像选择 + 平板使用天数 |
| 密码 | **不设密码**（平板本地使用，无网络验证） |
| 多账号 | **不支持**（单机游戏，一个用户名即可） |

### 3.2 与现有系统的兼容

| 现有系统 | 处理 |
|---------|------|
| LoginManager.cs | **废弃**，代码保留但不再使用 |
| AutoLoginUI.cs | **废弃**，加载动画移至平板开机流程 |
| auth.json | **废弃**，用户名改存PlayerPrefs("XiaomiAccount") |
| PlayerPrefs("Username") | 保留，作为小米账号的用户名 |

### 3.3 小米账号UI

## 四、加载流程优化

### 4.1 当前问题

AutoLoginUI的9阶段加载是假的——没有真实网络请求，只是协程延迟。浪费开发资源且给玩家虚假期待。

### 4.2 新方案

**平板开机动画 = 加载流程**

| 阶段 | 时长 | 内容 |
|------|------|------|
| 1. 黑屏 | 0.5s | 纯黑 |
| 2. 澎湃OS Logo | 1.5s | 澎湃OS 32 logo淡入+淡出 |
| 3. 锁屏 | 0.3s | 锁屏界面淡入 |
| 4. 解锁 | 0.3s | 光带扫过→桌面淡入 |
| **总计** | **~2.6s** | 比现在快得多 |

**后台初始化**：在开机动画期间并行加载必要资源（字体、UI面板、BGM），不阻塞玩家看到画面。

### 4.3 与Unity场景加载的关系

| 场景 | 新方案 |
|------|--------|
| Login场景 | **废弃**，不再需要 |
| TitleScreen场景 | **废弃**，功能合并到GameMainUI |
| VN_Test场景 | 保留，从RDA App或序章按钮进入 |
| StationSlice_V1场景 | 保留，从RDA App"继续运营"进入 |

**新的场景流转**：
```
游戏启动 → GameMainUI（平板桌面，唯一入口）
    ├─ [新游戏] → NewGameSetupUI → VN_Test → StationSlice_V1
    ├─ [继续] → StationSlice_V1
    └─ [设置/账号/其他] → 平板App窗口内操作
```

## 五、平台适配问题

### 5.1 Android平台

| 问题 | 影响 | 解决方案 |
|------|------|---------|
| **返回手势** | 从屏幕左/右边缘滑动→触发Android系统返回→直接退出游戏 | Unity设置：`Input.backButtonLeavesApp = false`；或在AndroidManifest中禁用系统手势区域 |
| **底部导航栏** | 三键导航栏占用屏幕空间 | 全屏沉浸模式：`Screen.fullScreen = true` + Android全屏flag |
| **触屏交互** | 平板桌面的点击/hover适合触屏 | 天然适配，无需特殊处理 |
| **屏幕比例** | 不同Android设备屏幕比例不同 | UI Toolkit自适应布局（已有） |

**关键修复**：Android返回手势问题
```xml
<!-- AndroidManifest.xml -->
<activity android:excludeFromRecents="true"
          android:theme="@style/UnityThemeSelector">
    <!-- 禁用系统返回手势 -->
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>
```
或者在Unity中：
```csharp
// 禁用Android返回键退出
Input.backButtonLeavesApp = false;
```

### 5.2 Windows平台

| 问题 | 影响 | 解决方案 |
|------|------|---------|
| **鼠标交互** | 平板桌面设计为触屏，鼠标操作不够自然 | 增加鼠标hover效果（已有）+ 右键菜单（可选） |
| **窗口模式** | 默认窗口模式下平板效果打折 | 默认全屏模式 |
| **分辨率** | 不同显示器分辨率不同 | UI Toolkit自适应 + ScreenScaler |
| **键盘快捷键** | 键盘操作需要映射 | 空格=解锁/确认，ESC=返回/关闭，方向键=导航 |

**鼠标→触屏映射**：
- 鼠标左键 = 触屏点击（已有）
- 鼠标hover = 触屏长按预览（可选）
- 鼠标滚轮 = 页面滚动
- 无需右键菜单（平板没有右键）

### 5.3 iOS/iPadOS平台（未来）

| 问题 | 影响 | 解决方案 |
|------|------|---------|
| **手势冲突** | iOS底部上滑=回到主页，侧滑=返回 | 与Android相同方案 |
| **安全区域** | 刘海/圆角/Home Indicator | UI Toolkit Safe Area适配 |
| **性能** | iOS设备性能差异大 | 低配模式（降分辨率/关闭动画） |

### 5.4 跨平台策略

| 策略 | 描述 |
|------|------|
| **输入抽象层** | 统一处理触屏/鼠标/键盘输入，上层代码不感知具体设备 |
| **手势冲突检测** | 检测是否在Android/iOS边缘区域，禁用系统手势 |
| **自适应布局** | 所有UI使用相对定位+锚点，不硬编码像素位置 |
| **平台检测** | `Application.platform` 运行时检测，调整交互方式 |

## 六、实施计划

### 第一阶段：废弃旧系统（最小改动）

1. **修改GameMainUI.cs**：开机时直接加载平板桌面（跳过Login/TitleScreen）

8. **平板开机动画**：黑屏→Logo→锁屏→桌面，总时长<3秒

10. **场景切换优化**：VN→经营的过渡使用平板锁屏过渡

### 第四阶段：平台适配

11. **Android返回手势修复**：`Input.backButtonLeavesApp = false`

### 8.3 命名系统（账号名）

**设计原则**：账号名不是一开始就设置的，而是在**剧情发展中自然出现**。

**触发时机**：序章prologue_02_day0中，导师给0721号时，需要输入用户名。

```
导师："这辆0721号需要注册一个使用者账号。你想叫什么？"
[输入框：请输入你的名字]
```

**实现方案**：

| 阶段 | 触发 | 内容 |
|------|------|------|
| 序章Day0 | 导师给0721号 | "需要注册账号"→弹出输入框→玩家输入用户名 |
| 跳过序章 | 答题开始前 | "请先注册小米账号"→弹出输入框→玩家输入用户名 |
| 后续使用 | 各处引用 | 岁月称呼用户名、RDA显示"欢迎，{用户名}" |

**默认值**：如果玩家跳过输入，使用"旅人"作为默认用户名。

**存储**：PlayerPrefs("XiaomiAccount") = 用户名

**与现有系统的关系**：
- 现有LoginManager的auth.json → 废弃
- 现有PlayerPrefs("Username") → 迁移到PlayerPrefs("XiaomiAccount")
- TitleScreen的用户名显示 → 改为从PlayerPrefs("XiaomiAccount")读取
