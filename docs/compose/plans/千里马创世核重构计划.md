# 千里马创世核重构计划

> 计划版本：v1.0  
> 状态：规划中  
> 分工：此计划定义任务层级，AI 逐步执行

---

## 一、重构目标

千里马创世核是**一切游戏世界差异的底层来源**。重构完成后，它应：

1. **作为独立模块**——可被其他系统依赖，不依赖其他系统
2. **确定性随机**——同一 seed 产生完全相同的世界
3. **完整可编码**——所有字段、算法、约束在文档中可直接转为 C# 代码
4. **可验证**——每个种子可通过 7 项验证
5. **可扩展**——新增种子无需修改算法

## 二、任务层级

### Layer 1：世界种子数据模型（T16.1）

**目标**：定义 `WorldSeedData` 的完整字段、类型、约束、JSON 序列化。

| 子任务 | 内容 | 产出 |
|--------|------|------|
| 1.1 城市数据 | 类型/population/population_growth/坐标/industries/dependencies/渗透/政治/区域/NPC | 完整字段表 |
| 1.2 依赖图 | imports/exports 有向图结构、强连通约束 | 数据结构 |
| 1.3 资源分布 | pattern(3种)/critical_nodes/bottleneck_risk/intervention_prob | 枚举+字段 |
| 1.4 政治倾向 | 全局倾向+城市级倾向+周期长度+favor(0-1)+stability(0-1) | 字段 |
| 1.5 铁路边 | from/to/travel_time/capacity 列表 | 字段 |
| 1.6 全局规则 | incident_base_chance/trust_decay/fiscal_growth/repair_cost_mult | 字段 |
| 1.7 趋势线 | 5条初始值+抖动范围 | 字段 |
| 1.8 元数据 | seed_id/name/version/seed_code/year | 字段 |

**验证**：JSON schemas 校验通过、所有字段有默认值

---

### Layer 2：确定性生成算法（T16.2）

**目标**：`WorldGenerator.Generate(int seed)` 的完整算法，含伪代码。

| 子任务 | 内容 | 算法参考 |
|--------|------|----------|
| 2.1 城市生成 | 4-7个城市、类型分配、人口、坐标（随机散布800×600）、产业 | 确定性随机 + 权重表 |
| 2.2 依赖图生成 | 有向图强连通闭环、入度/出度计算、关键节点识别 | 有向图生成 + 强连通检验（Kosaraju） |
| 2.3 资源分布生成 | 按概率抽样 pattern、计算 critical_nodes、bottleneck_risk | 权重随机 |
| 2.4 政治倾向生成 | 全局倾向抽样、城市级偏移、周期长度、favor/stability | 马尔可夫链 |
| 2.5 铁路边生成 | 城市间最小生成树（MST）+ 额外随机边、travel_time 按距离算 | Kruskal/Prim + 随机边 |
| 2.6 趋势线生成 | 5条线基准值±抖动 | 对称抖动 |
| 2.7 全局规则生成 | 按种子/难度/政治倾向查表 | 查表 |
| 2.8 种子注入 | WorldSeedData → GameData/SandRivalManager/EventManager/OrderManager | 注入点 |

**验证**：同一seed → 同一JSON；不同seed → 结构不同；闭环检验通过

---

### Layer 3：预设种子库（T16.3）

**目标**：5个可发布种子 + 3个调试种子，完整 JSON 填充。

| 种子 | 类型 | 特点 |
|------|------|------|
| seed_001 雾峰标准 | 平衡型 | 新手推荐，分散型资源 |
| seed_042 资源危机 | 集中型 | 高难度，单点故障风险 |
| seed_077 政治风暴 | 政治干预型 | 叙事驱动，频繁政策变化 |
| seed_113 自由市场 | 分散型 | 经营驱动，高渗透开局 |
| seed_999 废土重生 | 极限 | 全低保，必须靠剧情 |
| seed_debug_1 最小线 | 调试 | 3城市/1条线/快速验证 |
| seed_debug_2 全集中 | 调试 | 所有依赖指向同一城市 |
| seed_debug_3 全分散 | 调试 | 无依赖闭环 |

**验证**：每个种子可加载、30天稳定运行

---

### Layer 4：种子编解码与分享（T16.4）

**目标**：seed_code 编解码 + 分享机制。

| 子任务 | 内容 |
|--------|------|
| 4.1 编码格式 | `RR-XXXXX-YYYYY`，5位hex+校验 |
| 4.2 解码器 | seed_code → int seed |
| 4.3 校验 | 校验和验证，无效 seed_code 报错 |
| 4.4 分享UI规格 | 输入框/复制按钮/验证提示 |

**验证**：编码→解码→生成与原始一致

---

### Layer 5：联动接口（T16.5）

**目标**：各系统从种子读取数据的 API 定义。

| 系统 | 接口 | 数据 |
|------|------|------|
| GameData | `WorldSeedData.Initialize()` | 覆盖初始趋势线 |
| SandRivalManager | `seed.GetCityPenetration(id)` | 城市渗透初始值 |
| EventManager | `seed.globalRules.incidentBaseChance` | 事件基准概率 |
| OrderManager | `seed.GetCityIndustries(id)` | 订单类型 |
| 区域解锁 | `seed.GetCityUnlockRegion(id)` | 区域归属 |
| 先民人事 | `seed.GetCityNpcPool(id)` | NPC池 |
| 叙事引擎 | `seed.politicalTendency` | 政治倾向基调 |

## 三、执行顺序

```
T16.1 Layer 1 数据模型  →  T16.2 Layer 2 生成算法  →  T16.3 Layer 3 预设种子
                                                              ↓
                        T16.5 Layer 5 联动接口  ←  T16.4 Layer 4 种子编解码
```

依赖关系：1→2→(3,4)→5（4 和 3 可并行）
