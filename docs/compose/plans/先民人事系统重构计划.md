# 先民人事系统重构计划

> 计划版本：v1.0  
> 代码状态：⚠️ 基础数据结构+G11招募已实现，隐藏机制和成长系统未实现  
> 当前代码：`Assets/Scripts/CrewManager.cs`（360行，5员工+G11招募+NPC记忆）

---

## 一、重构目标

先民人事系统是"**员工是活的人**"的系统——技能数字可见，但疲劳和忠诚不可见，通过行为流露。重构完成后：

1. **疲劳系统完整**——阈值/效率影响/连续工作/强制休息，疲劳通过行为流露而非数字
2. **忠诚度系统完整**——每日变化/效率影响/离职触发，忠诚通过态度感知
3. **技能成长曲线**——按国际铁路标准（非线性），师傅带徒+培训加速
4. **行为流露**——疲劳/忠诚→对话映射→VN变量注入
5. **招聘+流失**——招募渠道UI/新员工生成/离职事件

---

## 二、任务层级

### P1 疲劳系统（T44）

| 子任务 | 内容 | 实现位置 |
|--------|------|---------|
| 1.1 疲劳阈值 | DailyUpdate 中按疲劳区间(0-30/31-60/61-80/81-100)设置效率倍率 | CrewManager.DailyUpdate |
| 1.2 效率影响 | 疲劳→效率公式：30以下100%/31-60:90%/61-80:75%/81+:50% | CrewManager.GetEfficiency(id) |
| 1.3 连续工作 | 新增 consecutiveWorkDays，每日+1，休息日重置 | CrewManager |
| 1.4 强制休息 | 疲劳>80时自动设为休息日（疲劳不增长，恢复30） | DailyUpdate |
| 1.5 对话文本映射 | 疲劳区间→疲劳对话文本（供NarrativeEngine GAP7消费） | 新增方法 GetFatigueDialogue(id) |

### P2 忠诚度系统（T45）

| 子任务 | 内容 | 实现位置 |
|--------|------|---------|
| 2.1 忠诚度每日变化 | 工资按时+0.1/天，拖欠-1.0/天，连续工作>10天-1.0/天 | DailyUpdate |
| 2.2 忠诚度效率影响 | 90-100:+10% / 70-89:100% / 50-69:90% / 30-49:75% / 0-29:离职 | GetEfficiency |
| 2.3 离职触发 | 忠诚<30→10%/天；<0→立即离职，移除crew列表 | DailyUpdate |
| 2.4 对话文本映射 | 忠诚区间→忠诚对话文本 | GetLoyaltyDialogue(id) |

### P3 技能成长曲线（T46）

| 子任务 | 内容 | 实现位置 |
|--------|------|---------|
| 3.1 成长曲线表 | 按国际铁路标准（驾驶1200天/维修800天/管理600天/货运700天/服务500天） | 常量表 |
| 3.2 岗位匹配系数 | 核心技能匹配×1.0/非核心×0.5/不相关×0.2 | DailyUpdate 经验计算 |
| 3.3 师傅带徒 | 师傅等级≥4级×2.0/有师傅×1.5/无师傅×1.0 | 新增 SetMentor(徒弟,师傅) |
| 3.4 培训系统 | 200沙币/次，冷却7天，驾驶+3天/维修+4天 | 新增 Train(crewId) |

### P4 行为流露系统（T47）

| 子任务 | 内容 | 实现位置 |
|--------|------|---------|
| 4.1 疲劳对话映射 | 疲劳区间→对话文本（正常→轻度→中度→重度） | GetFatigueDialogue |
| 4.2 忠诚对话映射 | 忠诚区间→对话文本（忠诚→正常→冷淡→不满→敌对） | GetLoyaltyDialogue |
| 4.3 VN变量注入 | 疲劳/忠诚状态→VN变量（供 VNManager 剧本条件使用） | 新增 GetCrewDialogueFlags |
| 4.4 经营UI状态提示 | 在 UIManager 显示员工状态文字（不显示数字） | UIManager |

### P5 招聘+流失系统（T48）

| 子任务 | 内容 | 实现位置 |
|--------|------|---------|
| 5.1 招聘渠道UI | 社区推荐(免费/冷却30天)/广告(500沙币/15天)/猎头(2000沙币/60天) | 新建 RecruitmentUI |
| 5.2 新员工生成 | 从G11招募池或随机生成（年龄20-50/技能1-3级/忠诚50） | CrewManager |
| 5.3 流失系统 | 忠诚<30→10%/天；年龄>65→1%/月；离职通知 | DailyUpdate |
| 5.4 剧情离职 | 外部事件触发离职（供叙事引擎使用） | 新增 RemoveCrew(id) |

---

## 三、执行顺序

```
P1 疲劳系统 → P2 忠诚度系统 → P4 行为流露 → P3 技能成长 → P5 招聘+流失
```

P1和P2可并行，P3依赖P1的疲劳效率，P4依赖P1+P2的对话映射，P5可最后
