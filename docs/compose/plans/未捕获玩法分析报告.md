## 1. 多维订单系统

### 现状
当前只有 `GameData.cs` 中的 `DispatchPlan` 三维数组（保守/标准/加开），没有独立的订单系统。

### 可行性分析
✅ 可加入。与经济系统直接挂钩，难度中等。

### 修改方案
- 新建 `OrderManager.cs`，管理订单的生成、指派、结算
- 订单分三类：标准货运、紧急任务、情感剧情（乘客故事）
- 订单 JSON 数据驱动，存放在 `Resources/orders.json`
- 订单 chain（生产链）作为中期扩展

### 实现路径
```csharp
// OrderManager.cs 核心结构
[System.Serializable]
public class GameOrder
{
    public string id;
    public string type; // "freight" / "urgent" / "story"
    public string origin;
    public string destination;
    public int reward;
    public int deadlineDays;
    public string chainId; // 生产链ID，用于组合订单
    public int trustDelta;
    public string environmentTag; // 环境挂钩
}
```

- 新建 `docs/compose/specs/订单系统设计.md`

## 2. 时刻表与调度面板

### 现状
当前调度系统是三个固定方案的循环按钮（保守/标准/加开），无可视化调度面板。

### 可行性分析
⚠️ 需要较大改动。涉及UI系统重构，当前 `StationSlice_V1` 场景无调度面板。

### 修改方案
- 实现可视化调度面板：时间轴 + 拖放列车 + 冲突检测
- 冲突检测算法：区间树或排序扫描线
- 单轨/双轨标记影响冲突检测结果
- 列车的运行时间区间 `[(start,end), trackSegment]`

### 实现路径
```csharp
// 调度冲突检测
public class ScheduleConflictDetector
{
    public bool CheckConflict(TrainSchedule newSchedule, List<TrainSchedule> existingSchedules)
    {
        foreach (var existing in existingSchedules)
        {
            // 检测时间区间重叠 + 轨道重叠
            if (newSchedule.TrackId == existing.TrackId &&
                newSchedule.StartTime < existing.EndTime &&
                newSchedule.EndTime > existing.StartTime)
            {
                return true; // 冲突
            }
        }
        return false;
    }
}
```

### 优先级
P2（中期优化，UI工作量较大）

## 4. 节日与季节系统

### 现状
经济系统中有 `seasonModifier` 参数，但未实现完整的节日/季节系统。

### 可行性分析
✅ 可加入。与经济系统联动，改动量小。

### 修改方案
- 在 `GameData.cs` 中添加季节周期性（春/夏/秋/冬）
- 节日事件作为特殊事件，绑定到日期
- 节假日客流高峰 ×1.5，持续7天
- 收获季/旅游季影响供需

### 实现路径
```csharp
// 季节系统（添加到GameData.cs）
public enum Season { Spring, Summer, Autumn, Winter }

public static Season GetCurrentSeason()
{
    int month = Day % 360 / 30;
    if (month < 3) return Season.Spring;
    if (month < 6) return Season.Summer;
    if (month < 9) return Season.Autumn;
    return Season.Winter;
}

public static float GetSeasonModifier()
{
    Season s = GetCurrentSeason();
    // 春季：茶季，客流+20%
    if (s == Season.Spring) return 1.2f;
    // 夏季：旅游季，客流+15%
    if (s == Season.Summer) return 1.15f;
    // 秋季：收获季，货运+20%
    if (s == Season.Autumn) return 1.0f;
    // 冬季：客流-10%
    return 0.9f;
}
```

- 更新 `核心玩法循环.md` 添加季节系统章节
- 更新 `跨系统联动公式.md` 季节公式

### 优先级
P2（与核心经济直接相关）

## 6. NPC 记忆系统

### 现状
VN 系统已有角色人设、好感度阈值，但游戏机制层面无 NPC 记忆系统。

### 可行性分析
✅ 部分已有，可扩展。VN 系统的角色配置可以扩展。

### 修改方案
- 轻量"记忆+状态"系统：事件记录、情绪值、关系值、最近对话主题
- 上次行为影响：是否准时发车、是否送达重要物品
- NPC 动态反应：迟到会抱怨，连续准点会信任
- 不需要额外系统，在 `CrewManager.cs` 中扩展

### 实现路径
