# 岁月叙事引擎重构计划

> 计划版本：v1.0  
> 状态：规划中  
> 当前代码状态：⚠️ VN 引擎基础可用（VNManager/DialogueBox/JSONParser），AI 叙事层完全未编码

---

## 一、重构目标

岁月叙事引擎是"**世界在说话**"的系统——它读取世界种子、趋势线、角色关系，生成匹配当前世界状态的事件。重构完成后，它应：

1. **模板化叙事可运行**——阶段1：基于世界状态匹配模板，参数化生成新闻/对话/事件
2. **与创世核联动**——城市依赖图/资源分布/政治倾向直接驱动叙事可能性
3. **与现有系统集成**——挂接 GameData.AdvanceDay、VNManager、EventManager、OrderManager
4. **可扩展**——阶段2/3 可插入 LLM 而不改架构
5. **岁月角色活起来**——好感度/记忆解锁/双 AI 线可运行

## 二、任务层级

### Layer 1：叙事引擎核心数据模型（N1）

**目标**：定义 NarrativeContext、StoryPossibility、NarrativeTemplate 等核心数据结构。

| 子任务 | 内容 | 产出 |
|--------|------|------|
| 1.1 NarrativeContext | 世界状态快照：趋势线/阈值/角色状态/最近事件/种子数据 | 数据结构 |
| 1.2 StoryPossibility | 故事可能性：模板ID/匹配分数/冷却/条件 | 数据结构 |
| 1.3 NarrativeTemplate | 叙事模板：type/conditions/template/parameters/effects | 数据结构 + JSON |
| 1.4 CharacterState | 角色状态：好感度/疲劳/忠诚/记忆/最近对话 | 数据结构 |
| 1.5 ThresholdEvent | 阈值事件：趋势线/阈值方向/严重度 | 枚举+结构 |

**验证**：JSON 序列化/反序列化通过

---

### Layer 2：世界状态分析器（WorldAnalyzer）

**目标**：读取 GameData/SandRivalManager/CrewManager/创世核 的当前状态，输出 NarrativeContext。

| 子任务 | 内容 | 输入源 |
|--------|------|--------|
| 2.1 趋势线读取 | 读取 GameData 五条趋势线 + 变化方向 | GameData |
| 2.2 阈值检测 | 检测趋势线是否越过阈值（信任<0.40 等） | 核心玩法循环 §4 |
| 2.3 角色状态读取 | 读取 CrewManager 疲劳/忠诚 + 好感度 | CrewManager |
| 2.4 种子数据读取 | 读取创世核的 storyTags/politicalTendency/criticalNodes | WorldSeedData |
| 2.5 最近事件 | 最近 N 天事件历史（防重复/冷却） | EventManager 日志 |

**验证**：给定种子+GameData 状态 → 输出完整 NarrativeContext

---

### Layer 3：模板化叙事引擎（NarrativeEngine）

**目标**：NarrativeEngine 主入口 + StoryEvaluator + TemplateFiller。

| 子任务 | 内容 | 算法 |
|--------|------|------|
| 3.1 NarrativeEngine 主入口 | CheckForEvent(context) → 产出叙事事件 | 主调度 |
| 3.2 StoryEvaluator | 评估可能性：遍历模板→conditions 匹配→排序→冷却 | 多条件加权 |
| 3.3 TemplateFiller | 替换占位符：{city}/{player}/{value} 等 | 正则替换 |
| 3.4 模板 JSON 加载 | 从 Resources/ 加载 narrative_templates.json | Resources.Load |
| 3.5 冷却系统 | 同类事件 cooldown_days 内不重复 | 字典计数 |

**验证**：给定 NarrativeContext → 输出匹配的叙事文本

---

### Layer 4：叙事输出集成（VN/Event/Order）

**目标**：叙事引擎产出接入 VN 系统、EventManager、UIManager 简报。

| 子任务 | 内容 | 输出目标 |
|--------|------|---------|
| 4.1 新闻事件→全屏新闻 | 生成 FullScreenNews 格式文本 | VN 系统 |
| 4.2 对话事件→VN 对话 | 生成 DialogueBox 格式对话 | VN 系统 |
| 4.3 运营事件→GameData 简报 | 写入 Briefing/Notices 列表 | GameData |
| 4.4 任务事件→OrderManager | 生成临时订单 | OrderManager |
| 4.5 AdvanceDay 挂载 | 在 GameData.AdvanceDay 沙能竞争后调用 | GameData |

**验证**：叙事引擎产出 → 对应系统正确处理

---

### Layer 5：岁月角色系统（Character System）

**目标**：岁月好感度/记忆解锁/双 AI 线接口。

| 子任务 | 内容 | 触发条件 |
|--------|------|---------|
| 5.1 好感度系统 | 提升/降低机制 + 阈值（0-30/31-60/61-80/81-100） | 对话选择 + 互动 |
| 5.2 记忆解锁 | 好感度→解锁记忆片段（4 阶段） | 好感度阈值 |
| 5.3 岁月对话 | 日常对话模板（运营建议/回忆/悬念） | 好感度 + 阶段 |
| 5.4 手机 AI 接口（预留） | RDA 远程调用接口（API Key 配置） | P2 实现 |

**验证**：好感度变化 → 记忆片段解锁

---

### Layer 6：叙事节奏控制（Rhythm Control）

**目标**：按游戏阶段控制事件密度与类型分布。

| 子任务 | 内容 | 参数 |
|--------|------|------|
| 6.1 事件密度控制器 | 按 Day 调整事件触发概率 | 序章高→生存中→发展低 |
| 6.2 类型分布控制器 | 按趋势线/种子控制事件类型权重 | 运营40%/角色25%/竞争20%/政治15% |
| 6.3 冷却系统集成 | 同类型事件冷却期（7-30天） | 字典 |
| 6.4 叙事日志 | 记录已触发事件（防重复+供调试） | List |

**验证**：游戏 60 天，事件类型分布符合 6.2 表

## 三、执行顺序

```
N1 数据模型 → N2 世界分析器 → N3 模板引擎 → N4 输出集成
                                                      ↓
                N5 岁月角色系统 ← N6 节奏控制 ← 完成 N1-N4
```

依赖关系：1→2→3→4→(5,6)（5 和 6 可并行，但 5 依赖 4 的对话输出）
