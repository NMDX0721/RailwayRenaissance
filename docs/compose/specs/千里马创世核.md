## 一、设计哲学

### 1.1 核心问题

传统策略游戏的问题是：**第 N 次开局的体验只是第 1 次的微调**。事件表一样、城市连法一样、政治周期一样——玩家只是在背概率表。

千里马创世核要解决的是：**每次开局，世界底层结构不同，因此同一事件在不同世界有完全不同的含义**。

### 1.2 一句话定义

> 新游戏开局时，一个种子生成三样不可见但永久存在的东西：**城市依赖图、资源分布逻辑、政治倾向**。这三样东西决定了整个游戏世界可能发生什么、不可能发生什么。

### 1.3 结构随机 vs 传统随机

| 维度 | 传统随机（RNG） | 结构随机（千里马创世核） |
|------|----------------|------------------------|
| 本质 | 概率表抽签 | 世界骨架不同 |
| 事件来源 | "第10年有30%概率发洪水" | "矿区依赖能源城供电，能源城线断了，矿工失业→客流暴跌" |
| 玩家感知 | "今天运气不好" | "这条线太依赖那座城了，我当初不该那么运营" |
| 重复体验 | 背概率表，第3局就腻了 | 每次开局世界不同，策略重新适应 |
| 叙事关联 | 事件打断叙事 | 事件是世界的自然表达 |

## 三、世界生成算法

### 3.1 城市依赖图生成

```
输入：城市数量 N（4-6个），随机种子
输出：城市依赖图（有向图）

算法：
1. 为每个城市分配类型（随机，但保证至少1个 mining + 1个 agriculture）
2. 为每个城市分配 1-2 个产出资源（按类型预定义）
3. 为每个城市分配 1-2 个需求资源（不能与产出完全重叠）
4. 构建依赖边：城市A需要资源X → 找到产出X的城市B → 添加边 A→B
5. 验证闭环：从任意城市出发，沿依赖边应能回到起点（否则重新分配）
6. 计算依赖深度：被依赖次数最多的城市是"关键节点"
```

### 3.2 资源分布逻辑生成

```python
def generate_resource_distribution(seed):
    patterns = ["concentrated", "dispersed", "political"]
    weights = [0.35, 0.35, 0.30]  # 概率权重
    
    pattern = weighted_random(patterns, weights, seed)
    
    if pattern == "concentrated":
        # 1-2个城市产出所有关键资源
        # 单点失败 → 全图瘫痪，风险高
        critical_nodes = [main_city]
        bottleneck_risk = 0.35
        
    elif pattern == "dispersed":
        # 每个城市自己解决大部分资源
        # 断一条线影响不大，但效率低
        critical_nodes = []
        bottleneck_risk = 0.10
        
    elif pattern == "political":
        # 高价值资源集中，政府干预
        # 税率波动、限运、征用概率高
        critical_nodes = [resource_cities]
        bottleneck_risk = 0.25
        government_intervention_prob = 0.15  # 额外的政治风险
```

### 3.3 政治倾向生成

| 倾向 | 概率 | 核心机制 | 玩家感受 |
|------|------|----------|----------|
| 威权（authoritarian） | 30% | 政府强制干预，稳定优先 | 压力大但规则清晰 |
| 市场（market） | 40% | 价格波动，自由竞争 | 自由度大但风险自担 |
| 福利（welfare） | 30% | 补贴多，但效率低、债务高 | 安全但发展慢 |

**政治周期**：每 180 天（约 6 个月）一次政治周期切换，有 20% 概率切换倾向。

## 四、五条趋势线的种子初始化

### 4.1 基准值

| 趋势线 | 基准值 | 波动范围 | 种子影响 |
|--------|--------|----------|----------|
| 信任 (Trust) | 0.62 | ±0.05 | 城市类型影响（农业区信任高，工业区信任低） |
| 财政压力 (Fiscal) | 0.30 | ±0.05 | 资源分布影响（集中型压力低，分散型压力高） |
| 沙能渗透 (Sand) | 0.15 | ±0.05 | 城市基础值+政治倾向影响 |
| 政治压力 (Political) | 0.20 | ±0.05 | 政治倾向影响（威权初始高，福利初始低） |
| 设施老化 (Decay) | 0.30 | ±0.05 | 随机，与城市繁荣度负相关 |

### 4.2 阈值系统

| 趋势线 | 预警阈值 | 不可逆阈值 | 不可逆后果 |
|--------|----------|-----------|-----------|
| 信任 | <0.40 | <0.30 持续30天 | 代际断层：新人口默认不坐火车 |
| 财政压力 | >0.70 | >0.90 | 强制破产重组 |
| 沙能渗透 | >0.40 | >0.55 | 关键线路被沙能控制 |
| 政治压力 | >0.50 | >0.70 | 政府强制接管运营 |
| 设施老化 | >0.60 | >0.80 | 线路报废，需巨额重建 |

## 五、种子对游戏系统的影响映射

### 5.1 城市依赖图 → 经济系统

```
经济系统影响：
- 城市A依赖城市B的煤炭 → 如果A-B线中断，A的工业产出-50%
- 关键节点城市（被依赖最多）的线路中断 → 连锁反应
- 依赖闭环越短（直接依赖），系统越脆弱
- 依赖闭环越长（间接依赖），系统越稳定但效率低
```

### 5.2 资源分布 → 事件系统

```
事件系统影响：
- 集中型分布 → 事件集中在关键节点（单点故障型事件）
- 分散型分布 → 事件分散（多线同时受损型事件）
- 政治干预型 → 事件涉及政府（税率调整、限运令）
```

### 5.3 政治倾向 → 结算公式

```
同一问题，不同政治倾向的结算：
- 亏损时：
  - 威权：政府强制裁员，效率↓但成本↓
  - 市场：自由市场调节，票价↑但客流↓
  - 福利：政府补贴，成本不变但债务↑

- 事故时：
  - 威权：政府接管调查，运营暂停 3 天
  - 市场：公司和玩家自行协商赔偿
  - 福利：政府出面安抚，赔偿由政府承担 50%
```

## 六、实现方案

### 6.1 阶段1：预设种子（当前）

```
实现方式：
1. 手动定义 3-5 个预设种子（JSON 文件）
2. 放在 Resources/ 下，启动时加载
3. 新游戏时玩家选择种子（或随机选一个）
4. 种子数据在 GameData 初始化时注入

种子预设：
- "标准开局"（平衡型，推荐新手）
- "资源危机"（集中型，高难度）
- "政治风暴"（政治干预型，叙事驱动）
- "自由市场"（分散型，经营驱动）
- "废土重生"（全低保，极限挑战）
```

### 6.2 阶段2：程序生成

```
实现方式：
1. 新建 WorldGenerator 类（静态工具类）
2. 输入：int seed
3. 输出：WorldSeedData（JSON 序列化）
4. 使用确定性随机（System.Random(seed)）
5. 生成步骤：城市 → 依赖 → 资源 → 政治 → 趋势

核心接口：
  public static WorldSeedData Generate(int seed)
  public static WorldSeedData GenerateFromTemplate(string templateId)
```

### 6.3 阶段3：种子分享

```
实现方式：
1. 种子编码为短字符串（如 "RR-7A3F-B2C9"）
2. 玩家可分享种子码
3. 对方输入种子码生成相同世界
4. 支持排行榜：相同种子比谁经营得好
```
