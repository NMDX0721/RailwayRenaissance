## [S1] 问题

传统模拟经营游戏存在一个根本性问题：**操作即时生效，历史可以被抹去**。玩家降价 → 客流立刻上升；玩家涨工资 → 员工立刻满意；玩家大修 → 车辆立刻焕新。这种"操作=结果"的线性关系违背了现实世界的因果规律：

- 过去半年服务差 → 今天降价，乘客凭什么马上相信你？
- 过去长期压榨员工 → 今天涨工资，员工凭什么立刻忠诚？
- 过去长期不维护车辆 → 今天大修一次，设备为什么能回到新车状态？

**核心矛盾**：玩家可以轻易"翻盘"而不需要承担历史代价，导致游戏缺乏深度决策——因为任何错误都可以被立刻纠正。

## [S2] 解决原则

### 核心哲学

惯性意味着：**你每天做的不是选择，而是在承担过去的选择。**

- 今天发现的问题，可能是30天前埋下的种子
- 现在采取的操作，最快也要数天才能看到效果
- 某些历史痕迹永远无法消除，只能通过长期良好表现来"覆盖"
- 正向惯性同样存在——长期稳定运营会让后续经营越来越顺

### 统一惯性模型

```
效果值 = 操作值 × (1 - 惯性系数) + 历史基线 × 惯性系数
```

| 参数 | 含义 | 范围 |
|------|------|------|
| 操作值 | 当前操作产生的理论变化值 | 取决于操作类型 |
| 历史基线 | 过去30天加权平均值（近期权重指数衰减） | 归一化 0-1 |
| 惯性系数 | 历史对当前操作的影响力 | 0.0-1.0（**所有系统皆 > 0**） |

### 历史基线算法

```
历史基线(t) = 0.4 × D(t-1) + 0.3 × D(t-2) + 0.2 × D(t-3) + 0.1 × D(t-4)
```
其中 D(t-n) 为 n 天前的实际值。权重指数衰减，近期权重大。

### 遗留问题机制

当某个系统长期低于阈值时，会生成**遗留问题**——这是一个具体的、持久的负面状态，不会因为数值恢复而自动消失。

遗留问题的特征：
1. **具体性**：不是抽象数值，而是具体的事件/状态（如"USET营业点"、"事故记录"）
2. **持久性**：即使触发条件消失了，遗留问题仍然存在
3. **可清除性**（部分）：可以通过特定操作逐步清除（如"长期安全运营降低事故权重"）
4. **不可逆性**（部分）：某些遗留问题一旦产生就永远存在（如"两次事故记录"的标签）

## [S3] 各系统惯性参数

### 通用参数表

| 系统 | 惯性系数 | 历史基线窗口 | 遗留问题阈值 | 遗留问题示例 |
|------|---------|-------------|-------------|-------------|
| 客流 | 0.15 | 30天 | 满意度<40持续10天 | 乘客信任度下降（差评积累） |
| 员工满意度 | 0.12 | 30天 | 满意度<30持续7天 | 离职倾向上升 |
| 员工忠诚度 | 0.15 | 30天 | 忠诚<30持续5天 | 主动离职概率增加 |
| 沙能渗透 | 0.20 | 30天 | 渗透率>0.60持续15天 | USET建立营业点（永久竞争据点） |
| 政治关系 | 0.18 | 30天 | 关系<30持续7天 | 政治支持降级 |
| 车辆状态 | 0.10 | 30天 | 状态<40持续10天 | 状态上限降低10% |
| 技能成长 | 0.05 | 30天 | 连续20天不培训 | 技能停滞（不培训会缓慢倒退） |

### 系统详解

#### 客流惯性（系数 0.15）

**表现**：今天降价5% → 理论客流+10% → 实际仅+7%（30%被历史差评拖累）
**历史基线**：过去30天乘客满意度加权平均值
**遗留问题**：当满意度<40持续10天 → 生成"乘客信任下降"标记，即使后续满意度恢复，乘客增长仍受-5%惩罚，需持续30天高满意度才能消除

#### 员工满意度/忠诚度惯性（系数 0.12 / 0.15）

**表现**：今天涨工资15% → 理论满意度+15 → 实际仅+10（历史低工资拖累）
**历史基线**：过去30天满意度/忠诚度加权平均值
**遗留问题**：忠诚<30持续5天 → 员工获得"离职倾向"标记，即使忠诚恢复，仍有10%概率在30天内主动离职

#### 沙能渗透惯性（系数 0.20）

**表现**：今天投广告 → 理论渗透率-5% → 实际仅-3%（USET已扎根，难驱逐）
**历史基线**：过去30天渗透率加权平均值
**遗留问题**：渗透率>0.60持续15天 → USET在该城市建立营业点（永久竞争据点）。即使后续渗透率降至0.60以下，营业点仍在，USET随时可以低成本重启竞争

#### 政治关系惯性（系数 0.18）

**表现**：今天送礼 → 理论关系+10 → 实际仅+6（过去失信记录拖累）
**历史基线**：过去30天政治关系加权平均值
**遗留问题**：关系<30持续7天 → 政治支持降级，即使后续恢复，贷款利率永久+1%

#### 车辆状态惯性（系数 0.10）

**表现**：今天大修2000沙币 → 理论+40状态 → 实际仅+25（长期不维护的损耗不可逆）
**历史基线**：过去30天维护频率加权平均值
**遗留问题**：状态<40持续10天 → 车辆状态上限降低10%（从100降到90）。需持续30天每日维护才能恢复上限。**一次性大修不能解决长期不维护的问题，日常维护比偶发大修更有效**

#### 技能成长惯性（系数 0.05）

**表现**：今天培训一次 → 理论+3天经验 → 实际+2.85天（几乎无拖累）
**历史基线**：过去30天培训频率
**遗留问题**：连续20天不培训 → 技能停滞，技能会以每天0.2%的速度缓慢倒退，直到重新培训

## [S4] 集成方式

### 与现有代码的集成

惯性原则是**设计哲学**，不是独立模块——它通过修改现有系统的数值计算逻辑来实现。

**修改模式**：在每个系统的 `DailyUpdate()` 或核心计算函数中，将原"直接应用操作值"改为"通过惯性公式过滤后应用"。

**现有需要修改的系统**：
- `GameData.cs`（经济模拟）：客流计算、定价效果
- `CrewManager.cs`（人事系统）：满意度/忠诚度变化
- `SandRivalManager.cs`（竞争系统）：沙能渗透变化
- 政治系统：关系变化
- 车辆系统：状态变化

### 历史基线存储

- 每个惯性系统在 `GameData` 中新增 `List<float> historicalData`，存储最近30天的值
- 每天 `EndDay()` 时更新对应列表（移除最旧、添加最新）
- 历史基线 = 加权平均（权重：当天0.4，昨天0.3，前天0.2，三天前0.1）

### 遗留问题存储

- 在 `GameData` 中新增 `Dictionary<string, int> permanentEffects` 
- key = 事件类型（如"passenger_trust_down"、"uset_outpost"、"vehicle_cap_reduced"）
- value = 剩余持续时间（天）。-1 表示永久，正数表示 N 天后可消除

## [S5] 实现优先级

| 优先级 | 系统 | 理由 |
|--------|------|------|
| P0 | 客流惯性 + 遗留问题 | 最直观影响玩家感知，经济循环核心 |
| P0 | 车辆状态惯性 | 用户明确强调"车辆状态必须有惯性" |
| P1 | 员工满意度/忠诚度惯性 | 人事系统核心，影响游戏中期体验 |
| P1 | 沙能渗透惯性 + USET营业点 | 竞争系统核心，影响后期策略 |
| P2 | 政治关系惯性 | 影响最小，可后期加入 |
| P2 | 技能成长惯性 | 培训系统边缘，可最后加入 |

## 零、惯性原则——历史沉积系统（v2.0）

**核心哲学**：你不是在做选择，而是在承担过去的选择。今天的问题可能是30天前埋下的种子；现在采取的操作需要时间才能见效。

### 0.1 统一惯性模型

```
效果值 = 操作值 × (1 - 惯性系数) + 历史基线 × 惯性系数
```

| 参数 | 含义 | 范围 |
|------|------|------|
| 操作值 | 当前操作产生的理论变化值 | 取决于操作类型 |
| 历史基线 | 过去30天加权平均值（近期权重大） | 归一化 0-1 |
| 惯性系数 | 历史对当前操作的影响力 | 0.0-1.0（**所有系统皆 > 0**） |

### 0.2 历史基线算法

```
历史基线(t) = 0.4×D(t-1) + 0.3×D(t-2) + 0.2×D(t-3) + 0.1×D(t-4)
```

D(t-n) 为 n 天前的实际值。权重指数衰减，近期权重大。每个惯性系统在 GameData 中存 List<float>，每天 EndDay 更新。

- 每人 List<string> persistentEffects，key 为事件类型
- 部分可消除（30天良好表现可覆盖），部分永久（事故记录标记）
- 遗留问题触发时，NPC 对话和新闻中会体现

## 一、客流公式（含惯性）

```
每日客流[线路] = 基础人口 × 信任系数 × 季节系数 × (1 - 沙能渗透率) × 服务品质系数

其中：
- 基础人口 = 城市人口 × 0.001（约0.1%的日出行率）
- 信任系数 = 0.5 + 信任值 × 0.5（信任0.6时系数=0.8）
- 季节系数 = 1.0 ± 0.2（节假日/旅游季加成）
- 服务品质系数 = 1.0 + (乘务员等级 × 0.03)
- 沙能渗透率 = 该城市沙能渗透值

**惯性修正**（v2.0）：
客流的惯性系数为 0.15。实际客流变化受历史基线拖累：
```
当日客流 = 理论客流 × (1 - 0.15) + 理论客流(30日均值) × 0.15
```
同时，当乘客满意度 < 40 持续 10 天时触发遗留问题——"乘客信任下降"标记，即使后续满意度恢复，客流增长仍受 -5% 惩罚，需持续 30 天高满意度才能消除。

示例（雾峰村，人口8,000，信任0.6，渗透0.15，乘务员2级）：
日均客流 = 8000×0.001 × (0.5+0.6×0.5) × 1.0 × (1-0.15) × (1+2×0.03)
         = 8 × 0.8 × 1.0 × 0.85 × 1.06
         ≈ 5.77人/天（单趟）
单程上座率 = 5.77 / 30(容量) ≈ 19% → 约20%（与初期设定一致）
```

## 二、事故概率公式

```
事故概率[日] = 基础概率(0.5%) × 车辆老化系数 × 司机技能系数 × 维护系数 × 天气系数

其中：
- 车辆老化系数 = 1 + (100 - 车辆状态) / 100
  - 状态70时：1.30
  - 状态50时：1.50
  - 状态30时：1.70
- 司机技能系数 = 1 - (司机等级 × 0.12)
  - 司机3级时：0.64
  - 司机1级时：0.88
- 维护系数 = 1 - (近7日维护次数 × 0.08)
  - 维护3次：0.76
  - 维护0次：1.00
- 天气系数 = 1.0（正常）~ 1.5（恶劣）

示例（状态70，司机3级，本周维护2次，正常天气）：
事故概率 = 0.5% × 1.30 × 0.64 × 0.84 × 1.0 = 0.35%/天
月事故概率 ≈ 10%（约每月1次事故的10%概率）
```

## 三、信任变化公式（含惯性）

```
信任变化[事件] = 事故影响 + 服务影响 + 沙能影响 + 运营影响

其中：
- 事故影响 = -0.08 × 事故严重度（1.0-3.0）
- 服务影响 = +0.005/天（正常运营）
- 沙能影响 = -0.03/次（沙能广告攻势）
- 运营影响 = +0.01 × 准点率（准点率90%时+0.009/天）

**惯性修正**（v2.0）：
信任系数的惯性系数为 0.15。
```
当日信任变化 = 理论变化 × (1 - 0.15) + (30天信任均值 - 当前信任) × 0.15 × 0.1
```
长期信任积累会产生正向惯性——信任均值高时，即使偶尔失误，乘客也更宽容。

示例（一次轻微事故，严重度1.5）：
信任变化 = -0.08 × 1.5 + 0.005 + 0 + 0.009 = -0.106/天（事故当天）
恢复时间 = 0.106 / 0.014 ≈ 7.6天（恢复到事故前水平）
```

## 四、维护成本公式

```
维护成本[次] = 基础维护费 × 车辆损耗系数 × 机械师技能系数

其中：
- 基础维护费：日常100 / 保养500 / 深度2,000 / 大修10,000
- 车辆损耗系数 = 1 + (100 - 车辆状态) / 100
  - 状态70时：1.30
  - 状态50时：1.50
- 机械师技能系数 = 1 - (机械师等级 × 0.08)
  - 机械师3级时：0.76
  - 机械师5级时：0.60

示例（状态70，机械师3级，日常维护）：
维护成本 = 100 × 1.30 × 0.76 = 98.8沙币 ≈ 100沙币
```

## 五、燃料消耗公式

```
日燃料消耗 = 百公里油耗 × 运行里程 / 100 × 车辆状态系数

其中：
- 百公里油耗：58.5L/100km（固定值）
- 日运行里程：23km × 4单程 = 92km
- 车辆状态系数 = 1 + (100 - 车辆状态) / 200
  - 状态70时：1.15
  - 状态50时：1.25

示例（状态70）：
日油耗 = 58.5 × 92 / 100 × 1.15 = 61.9升/天
月油耗 = 61.9 × 30 = 1,857升
月燃料费 = 1,857 × 15 = 27,855沙币
```

## 六、收入公式

```
日收入 = 客运收入 + 货运收入 + 其他收入

客运收入 = ∑(乘客数 × 票价) × 票价倍率
- 票价：35沙币/人（基准价，可随经营姿态浮动，见沙本位经济核 §0.9.2 弹性）
- 票价倍率：随经营姿态（民生优先×0.9 / 盈利优先×1.2 / 保守维持×1.0）与线路所在城市属性浮动，非固定标签

货运收入 = 货运量 × 23公里 × 0.5沙币/吨公里
其他收入 = 广告 + 站台小卖 + 剧情补贴（按事件）
```

## 七、沙能渗透公式（含惯性）

```
沙能渗透变化[日] = 自然增长 + 广告影响 - 公关效果 - 事故影响

自然增长 = +0.0015/天
广告影响 = +0.05/次（沙能行动轮）
公关效果 = 玩家公关投入 × 0.0001/沙币
事故影响 = 沙能事故 × 0.02/次（沙能发生事故时）

**惯性修正**（v2.0）：
沙能渗透的惯性系数为 0.20——所有系统中最高，因为 USET 一旦扎根，很难驱逐。
```
当日渗透变化 = 理论变化 × (1 - 0.20) + (30天渗透均值 - 当前渗透) × 0.20 × 0.05
```

**遗留问题**：当渗透率 > 0.60 持续 15 天，USET 在该城市建立营业点（永久竞争据点）。
即使后续渗透率降至 0.60 以下，营业点仍在——USET 可随时低成本重启竞争。
```

## 八、员工疲劳公式

```
疲劳增长[日] = 工时/标准工时 × (1 - 休息品质)

其中：
- 标准工时：8小时
- 工时：根据岗位（司机10h，其他8h）
- 休息品质：0.7（简陋）~ 1.0（良好）

疲劳影响：
- 疲劳>0.7：效率-20%，事故概率+15%
- 疲劳>0.9：强制休息3天
```

## 九、综合示例：一个完整游戏日（含惯性）

```
假设状态：第15天，雾峰村-矿区线，信任0.58，状态68，沙能渗透0.16

1. 计算客流（含惯性）：理论5.5人/趟，30天均值4.8人/趟
   实际 = 5.5×0.85 + 4.8×0.15 = 5.4人/趟 → 单程上座率18%
2. 计算收入：5.4 × 35 × 4趟 = 756沙币/天（比无惯性少14沙币）
3. 计算燃料：61.9升 × 15 = 929沙币/天
4. 维护成本（标准）：120沙币/天
5. 工资（安全优先）：90,000/30 = 3,000沙币/天
6. 事故概率：0.38%/天（低风险）
7. 信任变化（含惯性）：理论+0.014，30天均值0.56
   实际 = 0.014×0.85 + (0.56-0.58)×0.015 = 0.0119/天
8. 沙能渗透（含惯性）：理论+0.0015，30天均值0.155
   实际 = 0.0015×0.80 + (0.155-0.16)×0.01 = 0.00115/天
9. 日净收入：756 - 929 - 120 - 3,000 = -3,293沙币/天
10. 月化净收入：-98,790沙币/月
```

> 结论：纯运营亏损约10万沙币/月，剧情补贴（约5-8万沙币/月）是生存关键。
