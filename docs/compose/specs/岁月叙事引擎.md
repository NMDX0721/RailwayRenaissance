# 岁月叙事引擎

> 曾用名：AI系统实现计划  
> 版本：v2.0  
> 设计原则：AI 分析世界状态生成事件，结构随机驱动，渐进式实现

---

## 一、设计哲学

### 1.1 AI 在这个游戏里的角色

AI 只有一件事：**分析当前世界状态，生成对应的事件**。

不是从硬编码模板列表里随机挑选，而是：
- 读取种子衍生的底层结构（城市依赖图、资源分布、政治倾向）
- 读取五条趋势线的当前位置
- 读取玩家与角色的关系、角色与角色的关系
- 输出一个结构和时机都匹配当前世界状态的事件

### 1.2 与"结构随机"的关系

世界种子决定了事件的"可能性空间"，AI 在此空间内选择最合适的表达。同一个种子不会产生两局完全相同的体验，因为 AI 的每一次生成都受当前趋势线位置和玩家历史行为的影响。

### 1.3 实现形态

| 阶段 | 实现方式 | 说明 |
|------|---------|------|
| 阶段1（当前） | 模板化 AI | 基于世界状态匹配模板，参数化填充 |
| 阶段2（开发期） | 本地 LLM 服务 | Python FastAPI + llama.cpp，分析世界状态后生成 |
| 阶段3（发行期） | 嵌入式推理 | llama.cpp DLL / Unity Sentis，语言模型本地推理 |

## 五、AI 助手设计（手机 + 岁月联动）

### 5.1 设计思路

主角随身携带一部手机，手机里有一个 AI 助手。这个助手可以：
- 根据当前运营数据给出调度建议
- 回答玩家关于游戏机制的问题
- 在关键时刻推动剧情

**用户侧**：AI 助手由玩家自己的 API Key 驱动（如 MiMo / OpenAI / 本地模型），玩家自行配置，游戏本身不承担模型成本。

**叙事侧**：AI 助手解释为主角以荣誉研究生身份访问金日成综合大学的服务器，调用自己改良后的李式调度算法（RDA）进行实时计算。即：**玩家的 API 调用被包装成主角在远程调用学校服务器的 RDA 接口**。

### 5.2 叙事包装

```
现实层面：玩家配置 API Key → 游戏发起 HTTP 请求 → LLM 返回建议
世界观层面：主角掏出手机 → 访问学校服务器 → RDA 返回调度方案
```

### 5.3 界面形态

- 手机界面可作为游戏内的一个独立面板（UI 中的"手机"按钮）
- 助手以文字对话形式呈现建议
- 岁月可在特定剧情中切入同一渠道（"你的手机收到了来自 0721 号的消息"）

### 5.4 与现有系统关系

- 岁月（0721 号沙子飞猪号搭载的 AI 原型）是**独立于手机 AI 的存在**——岁月是 2053 年制造、沉睡 23 年的强 AI 原型，手机 AI 是主角日常使用的工具 AI
- 两条 AI 线可以产生剧情张力：手机 AI 理性、精确（RDA 的延伸）；岁月感性、不完美（被封印的强 AI）
- 后期可发展为"手机 AI 与岁月产生交互"的剧情线
