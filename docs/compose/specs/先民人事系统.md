# 先民人事系统（Seonmin Personnel System）

> 版本：v2.0  
> 设计原则：减少数字化输入，像现实一样——疲劳和忠诚不出现在界面上，而是通过言行流露。  
> 关联：角色设定.md、沙本位经济核.md、跨系统联动公式.md
> 代码状态：⚠️ 基础数据结构已实现，隐藏机制和成长系统未实现

---

## 一、设计哲学

> 每位员工是一个"人"，不是一串数值。技能数字可见，但疲劳和忠诚不可见——玩家通过观察员工言行来推断。

### 1.1 可见与不可见

| 属性 | 可见性 | 展示方式 | 设计理由 |
|------|--------|----------|----------|
| 技能等级 | ✅ 可见 | 数字（1-5级） | 玩家需要知道谁适合做什么 |
| 技能潜力 | ✅ 可见 | 星级（1-5⭐） | 玩家需要知道培养谁值得 |
| 岗位 | ✅ 可见 | 文字标签 | 玩家需要知道谁在做什么 |
| **疲劳** | ❌ 不可见 | 无数字，通过行为流露 | 像现实一样，你看不到同事的"疲劳HP" |
| **忠诚** | ❌ 不可见 | 无数字，通过态度感知 | 你看不到员工的"忠诚进度条" |
| 工资 | ✅ 可见 | 数字 | 玩家需要做成本预算 |

### 1.2 行为流露机制

疲劳和忠诚不显示数字，而是通过以下方式"流露"：

```
疲劳度高时：
  - 对话文本变化："今天有点累了..." → "不太舒服" → "...（沉默）"
  - 语音语调变化（文本描述）："声音正常" → "声音疲惫" → "声音沙哑"
  - 操作效率下降：从100%逐渐降到60%
  - 事故率上升：从基准值逐渐升到3倍
  - 极端情况：强制休息（"老陈今天没来上班"）

忠诚度低时：
  - 对话变得敷衍："嗯" → "好的" → "随便吧"
  - 拒绝加班："今天想早点走"
  - 事故后态度变化：从"积极处理"到"抱怨"
  - 极端情况：离职（"小芳留下了辞职信..."）
```

## 二、员工数据模型

### 2.1 完整模型（代码现有 + 设计需要）

```csharp
[Serializable]
public class CrewMember
{
    // === 基础信息（现有） ===
    public string id;           // 唯一标识
    public string name;         // 显示名称
    public int age;             // 年龄
    public string role;         // 当前岗位
    public int fatigue;         // 疲劳值（内部，0-100）
    public int loyalty;         // 忠诚度（内部，0-100）
    public SkillData[] skills;  // 技能数组
    
    // === 新增字段（设计需要） ===
    public int consecutiveWorkDays;  // 连续工作天数
    public int totalWorkDays;        // 总工作天数
    public float efficiency;         // 当前效率（受疲劳/忠诚影响）
    public string emotionalState;    // 情绪状态（"正常"/"疲惫"/"不满"/"兴奋"）
    public List<string> dialogueFlags;  // 对话标记（影响VN对话内容）
    public float accidentRiskModifier;  // 事故风险修正
}
```

### 2.2 技能数据结构

```csharp
[Serializable]
public class SkillData
{
    public string skillName;   // 技能名: "driving"/"repair"/"management"/"service"/"freight"
    public int level;          // 当前等级 (0-5)
    public int maxLevel;       // 潜力上限 (1-5)
    public int exp;            // 当前经验值
    public int expToNext;      // 升到下一级所需经验（由成长曲线决定）
}
```

## 三、岗位系统

### 3.1 岗位需求

| 岗位 | 核心技能 | 最低等级 | 建议人数 | 技能匹配加成 | 不匹配惩罚 |
|------|----------|----------|----------|-------------|-----------|
| 司机 | 驾驶 | 3级 | 1-2人 | +20%效率，事故率-30% | 等级不足：效率×0.5，事故率×2 |
| 机械师 | 维修 | 2级 | 1人 | +20%效率，维护成本-15% | 等级不足：维护成本+30% |
| 乘务员 | 服务 | 1级 | 1-2人 | +15%效率，信任+0.005/天 | 不匹配：信任-0.005/天 |
| 站务员 | 管理 | 1级 | 1-2人 | +10%效率，售票效率+10% | 不匹配：客流-5% |
| 调度员 | 管理 | 2级 | 1人 | +15%效率，准点率+10% | 不匹配：准点率-10% |

### 3.2 初始配置困境

**只有5人、5个岗位，人手全面紧张**：

| 问题 | 现状 | 影响 |
|------|------|------|
| 司机缺口 | 只有老陈(5级)够格 | 无法轮班，老陈疲劳风险极高 |
| 机械师独苗 | 只有张工(5级) | 张工请假=无人维修 |
| 无人替补 | 每个岗位刚好1人 | 任何一人请假会影响运营 |

**解决方案**：玩家必须选择一种分配策略，每种策略都有代价。

### 4.2 成长曲线（v3.0——基于真实培训年限，接入波动/惯性）

> 以下为各子技能的基准成长天数（不含波动和惯性），基于各国铁路真实培训年限推算。实际游戏内日增长将接入 FluctuationEngine 加权波动和惯性沉积系统进行调制。

**各子技能 0→1 至 6→7 基准成长天数：**

| 等级晋升 | 行车·司机（中国） | 调车员（中国） | 值班员（中国） | 调度员（中国） | 真实参考 |
|---------|-----------------|--------------|--------------|--------------|---------|
| 0→1 | 180天 | 90天 | 90天 | 180天 | 司机岗前培训3-6个月 |
| 1→2 | 180天 | 180天 | 180天 | 180天 | 副司机6个月+6万公里 |
| 2→3 | **730天** | 365天 | 365天 | 365天 | 副司机→司机**2年+10万公里** |
| 3→4 | 365天 | 365天 | 365天 | 365天 | 指导司机选拔约1年 |
| 4→5 | 1095天 | 730天 | 730天 | 730天 | 高级指导司机4年+评审 |
| 5→6 | 1460天 | 1095天 | 1095天 | 1095天 | 首席司机约8年 |
| 6→7 | 1825天 | 1460天 | 1460天 | 1460天 | 特级司机约10年+ |

| 等级晋升 | 机车钳工（德国） | 车辆钳工（英国） | 线路工（日本） | 信号工（英国） | 列车员（国际） |
|---------|----------------|----------------|--------------|--------------|--------------|
| 0→1 | 180天 | 90天 | 90天 | 180天 | 30天 |
| 1→2 | 365天 | 180天 | 180天 | 365天 | 90天 |
| 2→3 | 730天 | 365天 | 365天 | 730天 | 180天 |
| 3→4 | 1095天 | 730天 | 730天 | 1095天 | 365天 |
| 4→5 | 1460天 | 1095天 | 1095天 | 1460天 | 730天 |
| 5→6 | 1095天 | 1460天 | 1460天 | 1095天 | 1095天 |
| 6→7 | 1825天 | 1825天 | 1825天 | 1825天 | 1460天 |

**基准日增长率（波动/惯性调制前）：**

```
日增长 = 14.3 / 当前等级晋升所需天数

示例：司机 2→3（730天）→ 基准日增长 = 14.3 / 730 ≈ 0.020/天
示例：列车员 1→2（90天）→ 基准日增长 = 14.3 / 90 ≈ 0.159/天
```

**波动/惯性调制公式（最终日增长）：**

```
最终日增长 = 基准日增长 × 岗位匹配系数 × 追赶加成 × 惯性系数 × 波动系数 × 事件修正

其中：
- 岗位匹配系数：核心×1.0 / 同系统×0.6 / 低门槛跨系×0.3 / 高门槛跨系×0.1（见 4.3）
- 追赶加成：母技能高于子技能时生效，差距越大加成越高
- 惯性系数：历史基线对当前成长的拖累或助力（见惯性原则设计）
- 波动系数：FluctuationEngine 提供的 3D Simplex 噪声波动
- 事件修正：师傅传授×2.0 / 培训×1.5 / 负面事件×0.5 等
```

**母技能成长：**

```
母技能等级 = Σ(子技能等级 × 子技能权重) / Σ(子技能权重)
子技能权重由岗位匹配度决定（见 4.3 节）
```

> 注意：以上数据为基准值，实际游戏中受 FluctuationEngine 的 L2 加权波动和惯性沉积系统影响，每日成长会在基准值附近浮动。波动幅度由 GlobalRules 中的 fluctuationIntensity 参数控制。

### 4.3 岗位匹配系数（v3.0——分层学习难度）

> 不同技能之间的学习难度不同——司机可以"依葫芦画瓢"学站务（低门槛），但学不了机辆（高门槛）。

| 关系 | 系数 | 示例 |
|------|------|------|
| 本职匹配 | ×1.0 | 司机→行车·司机，钳工→机辆·机车钳工 |
| 同系统子技能 | ×0.6 | 司机→行车·调车员（同属行车系统，可互相学习） |
| 跨系统·低门槛 | ×0.3 | 司机→站务·列车员（可观察模仿，如扫地、售票） |
| 跨系统·高门槛 | ×0.1 | 司机→机辆·机车钳工（需要专门技术训练，不能"看会"） |

**低门槛技能转移**：行车↔站务（可观察模仿）、线路→行车（观察线路即可了解行车）
**高门槛技能转移**：行车→机辆、行车→信号、站务→机辆、站务→信号（需专门训练）

## 五、隐藏机制详解

### 5.1 疲劳系统

**数值模型**（内部，不显示）：

```
每日疲劳增长 = 10（基础值）
  - 如果连续工作 > 7天：额外 +5/天
  - 如果岗位是司机：额外 +3/天（司机更累）
  - 如果当日有事故：额外 +15

每日疲劳恢复 = 5（休息日恢复 30）
  - 如果安排了休息日：当日疲劳不增长，恢复 30
  - 如果当日有培训：疲劳增长减半（培训=休息）

疲劳阈值（内部）：
  0-30：正常，效率100%，无副作用
  31-60：效率-10%，事故概率+5%，对话开始变化
  61-80：效率-25%，事故概率+15%，可能请假
  81-100：强制休息，对话明显疲惫
```

**行为流露对照表**：

| 疲劳区间 | 对话示例 | 行为表现 |
|----------|----------|----------|
| 0-30（正常） | "今天精神不错！" | 正常操作 |
| 31-60（轻度） | "有点累了..." | 偶尔走神，效率略降 |
| 61-80（中度） | "不太舒服，想休息一下" | 操作变慢，容易出错 |
| 81-100（重度） | "......"（沉默） | 强制休息，可能引发事故 |

### 5.2 忠诚度系统

**数值模型**（内部，不显示）：

```
忠诚度变化（每日）：
  - 工资按时发放：+0.1/天
  - 工资拖欠：-1.0/天
  - 事故发生（该员工涉及）：-5.0/次
  - 连续工作 > 10天无休息：-1.0/天
  - 获得培训：+2.0/次
  - 职位晋升：+5.0/次
  - 特殊事件（剧情）：±10.0
```

**惯性修正**（v2.0 新增）：
忠诚度有惯性系数 **0.15**——历史低忠诚度会使涨薪效果打折扣，员工需要时间重新信任你。

```
当日忠诚变化 = 理论变化 × (1 - 0.15) + 30天忠诚均值 × 0.15 × 0.1
```

**遗留问题**：当忠诚度 < 30 持续 5 天 → 员工获得"离职倾向"标记。即使后续忠诚度恢复，仍有 10% 概率在 30 天内主动离职。该标记可通过持续 30 天高忠诚度（>70）消除。

**核心体验**：长期压榨员工 → 即使今天涨工资，员工仍然半信半疑。历史伤害需要时间愈合，"过去的选择"在人事系统中尤为明显。

忠诚度影响：
  90-100：效率+10%，拒绝离职，积极加班
  70-89：正常效率，正常状态
  50-69：效率-10%，可能抱怨，拒绝加班
  30-49：效率-25%，可能罢工，准备离职
  0-29：强制离职（"xx留下了辞职信..."）

**行为流露对照表**：

| 忠诚区间 | 对话示例 | 行为表现 |
|----------|----------|----------|
| 90-100（忠诚） | "放心，有我在。" | 主动加班，事故时积极处理 |
| 70-89（正常） | "好的，我知道了。" | 正常工作 |
| 50-69（冷淡） | "嗯。"（敷衍） | 下班就走，事故时抱怨 |
| 30-49（不满） | "工资什么时候发？" | 可能罢工，事故时推卸责任 |
| 0-29（敌对） | "我不干了。" | 离职 |

## 六、招聘与流失系统

### 6.1 招聘

```
触发条件：线路扩张、员工离职、玩家主动招聘
招聘渠道：
  - 社区推荐：（免费，但技能随机）冷却30天
  - 广告招聘：（500沙币，技能较好）冷却15天
  - 猎头推荐：（2000沙币，高技能概率）冷却60天

新员工属性：
  - 年龄：20-50岁随机
  - 技能：1-3级随机（受渠道影响）
  - 潜力：1-4级随机
  - 初始忠诚：50
  - 初始疲劳：0
```

### 6.2 流失

```
触发条件：
  - 忠诚度 < 30：离职概率 10%/天
  - 忠诚度 < 0：立即离职
  - 特殊事件：剧情安排的离职/退休
  - 年龄 > 65：退休概率 1%/月

离职后果：
  - 该岗位空缺，效率下降
  - 可能需要调整其他员工岗位
  - 剧情触发（如果离职员工是核心角色）
```
